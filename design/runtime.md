# 连续场景运行：0.7.0

## 0.7 视野预绘

2026-10-16 用户明确选择全图逻辑先生成、画面按视野提前绘制，优先达到 2–5 秒加载。默认 scenePreload=false；旧全图预绘保留作诊断参考，不作为运行要求。CS 的原版任务模式开关、主层合并及刷新规则保持。

sceneOpen 仍同步准备全图光照、灯具转换、装饰索引和动态物件。首次画面延至同一进场流程内的 Camera.calc：此时原生出生点、镜头位置和缩放已经确定，避免先绘制旧位置。首屏按区域裁分批量绘制，复制到原来的 320 核心/40 边缘四层像素。实际画面覆盖包括相机震动；看不见的预留边距不再迫使加载时绘制整列相邻房间。

后续 sceneTick 必须先补齐实际视野，再从两块宽的邻近带选一个位置提前绘制，优先行进方向；已绘制区域保留到原生重绘或离开场景。此过程没有房间激活、实体重建或远处 AI 休眠。瞬移和突然缩放会同步补齐所需画面；普通行进预绘在 600 帧测试中没有视野缺块。预绘仍有长帧，不把 2–5 秒加载验收等同游玩帧率已恢复原版。

未绘制地形同样接收物理破坏；原有弹痕历史在首次绘图时重放，动态水从当前 Tile 状态生成。供电/断电走原生重绘，清除旧画面并按新的灯光/区域样式准备首屏。WB 只为已经生成的画面块建立覆盖层，借用像素的释放事件不变。

材质填充裁到原矢量遮罩的整数边界，加一像素余量，保持纹理原点和所有原生滤镜。相同区域画布的 12 pass/48 图层对照为逐像素一致。不同画布尺寸原先已有少量滤镜/抗锯齿差异，不能混用作本优化的单变量判断。

进场只缩短渐隐和无输入等待：仍由原版 exitStep 完成 20/19/18/16/1 的加载、生成、点击检查、控制恢复和 HUD 恢复。原生 clickReq>0 的等待保留。合并地图直接复用原 Tile，只有缺失房间位置创建填充 Tile。

当前构建只在包含 PermanentInjury 的 08A96759 宿主上定向替换 Grafon；4671 个无关方法/初始化、1015 个类布局和旧常量池索引保持。最终候选、测试和部署状态见[加载优化记录](../knowledge/experiments/loading-v07-20261016.md)。下文为历史设计与兼容边界。

0.6的实现与最新验收/部署状态见[本轮记录](../knowledge/experiments/native-v06-20261015.md)。下文保留历史设计推导，0.5的测试数字仅对应历史组合；本设计不承诺普通房间的稳定流畅度，也不承诺完整原版剧情、电路或任意容量已经兼容。

## 0.6 原版地图与预绘更新

设置nativeEnabled默认false并写入独立偏好文件。Game.enterToCurLand在原版Land构造后调用NativeSceneAdapter.prepare，只合并多个标准48×25主层房间；基地、后室和挑战保留原路径。原网格主层位置都别名到同一Location；对象链表、Tile物理边界、数组、出生点和交互坐标转换到全局。后室出入做局部/全局换算，gotoProb前更新所在区域坐标。Location.step在玩家/各对象执行前选择对应环境，结束恢复玩家所在区。

普通gotoLand复用Land，beginMission的新生成清除该地区地形历史和LAD灯具状态；随机任务读档回基地沿用原Game构造，不改为恢复原随机实例。静态Land按房间布局修订标记登记地形保存。当前实例不会因设置变动中途切换模式。

全覆盖区域图以每区域一次绘制分发到既有400×400底层像素（320核心+40边缘），工厂12pass；有洞地图回退3×3批量。游玩中增量更新仍用原320块。完成drawKusok后解除复用遮罩对临时Sprite/cacheAsBitmap的引用，避免原生缓存滞留。

sceneClear同步发出continuousSceneBeforeRasterClear供WB先释放旧借用覆盖层；新位置设置后、首次绘图前发出continuousSceneBeforeRaster供LAD转换灯具原图。sceneSynchronousRedraw能力允许LAD跳过旧延迟补绘，旧宿主仍走旧路径。continuousSceneResetGeneration携带地区ID，仅删除该地区灯具存档。

sceneCullRender默认true，每帧只隐藏视口外的原生/WB位图，不释放像素和逻辑；LAD同样只隐藏视口外灯具显示。SATS捕获临时显示全部块再恢复。光照图换bitmapData后重置smoothing=true。RV最终产物不变，WB仅加入等价透明邻域前缀计数和背景保护缓存。

用户已决定先做运行层，编辑器暂缓。目标是大的、无内部玩法边界的场景；原版房间仅作为测试资料。

单一 Location 持有全场景格子、单位、子弹与交互物。技术性的绘图窗口不能调用房间切换，不能重设实体状态。原版 48×25 格格式保持默认；扩展场景在 room 元素用 sceneWidth / sceneHeight 指定格数。

Grafon 的地形位图改为 320×320 像素的缓存块。每块持有前景、两层背景和水层；共用 400×400 的绘制暂存区，四边各留 40 像素用于阴影及边缘。显示对象仍以世界坐标摆放，绘入暂存区时减去块原点，最后裁出中心。原版动态物件显示层不重建。材质遮罩复用，减少每次准备缓存块时的显示对象分配。

0.3 按用户要求在原生进图阶段预绘全场，192 块在开放操作前全部生成，行走和瞬移均不淘汰或生成块。原镜头缓存策略保留为隔离对照开关。每块原生四层像素同时供显示 Bitmap 使用，以 scrollRect 裁去 40px 边缘；不再另存中心区副本。WallBlend 的覆盖层同样共用其输出像素。逻辑场景始终只有一个，缓存块没有玩法边界。

破坏首先由原版Bullet → Location.hitTile → Tile.die修改地形，再更新相交块。0.5弹痕范围由真实图形及固定帧、缩放、旋转、子图形与滤镜求保守包围，并计入原生alpha保存/恢复的完整影响范围；不再用固定中心距离排除大爆炸。未知边界保守全覆盖。喷漆按线段外扩50px、gwall按格、水按本格及下格。无关块revision不变，WB无需全图重算；同一次弹痕跨块、跨区使用同一随机帧，重放仅处理相交块。临时包围只缓存内存，不改变旧kind/args/stamp存档格式，长时痕迹成本仍待测。

原生copyChannel源矩形端点与目标点取整不同，弹痕alpha范围必须按世界坐标确定后再裁块。独立AIR实验覆盖165个小数/负坐标案例：源端点最接近整数且半数取偶，目标点向零截断；同值13.5的保存/恢复可能产生一像素采样偏移。不能把每块局部负坐标重新夹到零。最终大爆炸与分数坐标门禁已通过；大爆炸保留两个世界像素（重复gutter共4次）与全局参考不同，位于alpha框外且完整ARGB等于独立原生cut+draw。框内alpha必须完全一致，框外差异还受原生等价、单通道≤8和每例≤64像素共同限制；完整判定与失败历史见调查记录，不能表述为全局零误差。

背景装饰在原生setLight选定当前帧后建立空间索引，包含vis/erase/light与滤镜、边缘余量，按原画家顺序提供每块列表。宿主和WB复用索引，减少240块各扫603对象的重复工作；完整重绘重建索引，不确定图形保守保留。

普通 48×25 格地图仍使用原版 1920×1000 位图。切入大场景时换成块缓存，切回普通地图时释放缓存并恢复原画布；同一局返回大场景时复用原 Location。大场景在 GameData 和 World.landData 登记，以便原版 new Game / loadGame 重建地图定义。

第一份测试地图用 192×60 格（7680×2400 像素），包含长走廊、垂直空间、平台、敌人及可破坏地形。验证边界包括原版 1920/1000 像素边界与绘图窗口边界。

0.4起正式入口使用原版工厂12模板合并的192×75格关卡，240块常驻。只在原门槽兼容处打通外侧两格；区内格子、444物件标记与603装饰保留，编码加区域前缀，只留一个出生点。0.5场景XML不变，旧走廊继续作独立回归夹具。

## 镜头、地图与区域外观

0.5移除每帧setZoom(0)及isZoom锁定。0/1/2档按原版1920×1000参考尺寸求倍率，实际镜头边界保持全图；sceneEnsure与RV绘制视口均通过scaleV反算世界坐标。视口变化只刷新新增区域像素/单位掩膜缓存，不强制重跑FOV。setFonSize将背景覆盖与400px暂存图尺寸分开。

Land.createMap按实际Location最右/下边界扩展画布，保持原地图原点、每格像素及探索语义。CS只在大地图首次打开时居中，后续拖动缩放交给原控件；对齐测试需遵循Flash显示精度，不能容忍格子级错误。

sceneRegions的backwall/color/dark通过原生Location.colorFilter解析；320px块与1000px原房间高度不整除，四层必须按世界区域交集分别绘制、精确裁分合成，不能取块中心一种色覆盖全块。纹理坐标和背景装饰顺序保持，临时Location字段绘制后恢复。水与弹痕增量路径同样按区域裁分，不额外整图重绘。

静态darkness影响Grafon的遮暗与层间色变，Tile.visi/t_visi、retDark和视距属于逻辑光照/记忆。Location.lighting/lighting2使用真实空间尺寸；当前十二模板无独立视距/retDark/noblack等特殊区域选项，不新增虚构FOV规则。动态灯具与枪口仍由原生逻辑驱动，真实组合效果必须实测。

普通单位和箱子仅在已有Unit.setVisPos、Box.addVisual/runVis显示点更新基础区域色，不额外全场扫描。hero、ctrans=false及魔法武器tip5排除，ColorTransform八分量判断默认/上次区域基础色归属，避免覆盖冻结、念力、高亮；影子不染。UnitMerc独立arm附件未另加宿主接点。

allon/alloff保持原生单一Location全场供电/断电。sceneOpen进入时将全场开关颜色和暗度同步到原有区域样式对象，再重建surface与WB覆盖层；逐区域临时绘制不反向污染全场状态。最终Experience的14项检查通过，覆盖12区域、88背景帧、377实体基础色、240块重绘、像素变化和测试状态恢复。未设计十二份独立电路，也未穷举所有电门与开关后持久化；后房、跨层剧情、各区电路与原随机生成器未整体移植。

分块世界坐标适配必须覆盖 `backBmp2`，它的字段名带尾随数字。0.3的正则仅识别以Bmp结尾的字段，漏掉了此层的装饰与特殊格绘制，导致黑色图形按320px重复。0.4显式列出位图目标并断言替换数量，以工厂真实装饰和原生四层像素对照补齐覆盖；基础走廊上的移动/碰撞成功不能证明装饰层完整。

## 交互、入口与持久化

首次E继续走原生LOS。大场景在UnitPlayer.actions补owner有效性、同Location及持续直线遮挡，在crackAction补Y相同门槛；普通房间保持。沿原生owner几何中心和门本身例外，保留telemaster+portOn，Loot/comein仍需LOS。提示高亮不等于实际开取成功，未将全部拾取和念力路径泛化改写。

生产ContinuousSceneMod只注册地区、加载定义并提供信息页旅行按钮，不自动开档、移动角色或存测试槽。独立探针通过同一入口驱动，只接受隔离应用身份，正式清单不含测试驱动。弹痕像素探针会留临时私有图形类痕迹，只允许最后执行并退出，不能随后存档、旅行或重绘。

Game.save 在原版对象收集前保存稀疏 Tile 变化和破坏画面，存入 `Game.triggers["continuous_scene.terrain.v1"]` 的版本化 JSON。Location 构建后、渲染前按地区 ID、sceneRevision 和尺寸恢复；每次新的 Game 重置运行缓存。弹痕类以类名序列化，恢复时解析为 Class。该扩展补齐地形保存，不改变原版角色检查点规则。

## 视觉兼容与冻结来源

RV保留全场逻辑视线，只重画视口加四格余量的雾。子格视野在场变化时失效，首个粗判可见单位需要时复制，同帧复用；无可见单位不复制。0.5的快速访问仍每帧读取实际Tile并更新遮挡、水、拓扑和墙角记忆，不裁逻辑场或延迟更新。普通房间与classic保持原路径。

WB按块revision、世界纹理/噪声和共享材质缓存更新，区域覆盖精确裁分并防止跨区域色调污染明暗采样；保留已发布0.5.3半格/一击墙、破坏让位与消黑缝实现。两模组兼容均不写游戏Tile或原始地形像素。

RV冻结源commit为0735491e49d0d286ea8847017ae2fb64067a3c71，WB为f32e4a99643ccc901dc4f8e8caac29a6cde441b4，仅在CS的build/generated/rv-production和wb-production生成兼容源。不以其他模组HEAD代替发布源，不混入authority等WIP；诊断profile产物不作为最终性能或发布产物。

全场常驻消除移动时补画地形，仍有物理、光照、合成、内存与进图预绘成本。0.5两轮独占无插桩大图进图25,052/27,851ms，开枪中位/P95/最大分别43.5/63/202ms、37/52/154ms（旧基线47/193/325ms）；首轮关闭RV/WB的诊断阶段仍有313ms尖峰，原因尚未完全分离。两轮进程Private/WorkingSet峰值分别3031/2966MB、2709/2634MB，均高于旧基线2505/2440MB；未改善内存。复测另存，不择优覆盖首轮，不宣称无限地图、稳定30帧或任意剧情兼容。
