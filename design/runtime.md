# 第一阶段：连续场景运行

用户已决定先做运行层，编辑器暂缓。目标是大的、无内部玩法边界的场景；原版房间仅作为测试资料。

单一 Location 持有全场景格子、单位、子弹与交互物。技术性的绘图窗口不能调用房间切换，不能重设实体状态。原版 48×25 格格式保持默认；扩展场景在 room 元素用 sceneWidth / sceneHeight 指定格数。

Grafon 的地形位图改为 320×320 像素的缓存块。每块持有前景、两层背景和水层；共用 400×400 的绘制暂存区，四边各留 40 像素用于阴影及边缘。显示对象仍以世界坐标摆放，绘入暂存区时减去块原点，最后裁出中心。原版动态物件显示层不重建。材质遮罩复用，减少每次准备缓存块时的显示对象分配。

镜头可见区的缺块立即补齐；正常移动时，每帧预先绘制一块相邻区域。缓存保留可见区及一圈相邻块，远处位图释放。瞬移或首次进入需要同步绘制多块，仍可能停顿；正常步行应在显示前完成预绘。光照使用全场景的小尺寸格子图，地形、碰撞和战斗继续在整个 Location 内执行。

破坏首先由原版 Bullet → Location.hitTile → Tile.die 修改地形，再调用 Grafon 更新已驻留的画面块。弹痕、血迹等在 Location 对应的记录中保存，离开绘图缓存后按同一随机画面帧重放。地形本体始终在内存中；缓存淘汰不会恢复已破坏碰撞。记录目前为线性数组，长时间大量弹痕的性能尚未测量。

普通 48×25 格地图仍使用原版 1920×1000 位图。切入大场景时换成块缓存，切回普通地图时释放缓存并恢复原画布；同一局返回大场景时复用原 Location。大场景在 GameData 和 World.landData 登记，以便原版 new Game / loadGame 重建地图定义。

第一份测试地图用 192×60 格（7680×2400 像素），包含长走廊、垂直空间、平台、敌人及可破坏地形。验证边界包括原版 1920/1000 像素边界与绘图窗口边界。

生产 ContinuousSceneMod 只注册地区、加载定义并提供信息页旅行按钮；不会自动开档、移动角色或存测试槽。独立 ContinuousSceneProbe 通过同一按钮驱动测试，仅接受 `pfe-modsettings-continuous-scene` 身份。这个前缀也避免触发其他模组的通用测试驱动。正式清单只新增生产模块。

Game.save 在原版对象收集前保存稀疏 Tile 变化和破坏画面，存入 `Game.triggers["continuous_scene.terrain.v1"]` 的版本化 JSON。Location 构建后、渲染前按地区 ID、sceneRevision 和尺寸恢复；每次新的 Game 重置运行缓存。弹痕类以类名序列化，恢复时解析为 Class。该扩展补齐地形保存，不改变原版角色检查点规则。

RealisticVision 保留全场逻辑视线判定，只重画镜头附近加四格余量的雾，并对该区域做模糊和显示裁切。普通房间保持原绘图范围。WallBlend 对每个常驻块建立独立前景/背景覆盖层，使用世界坐标纹理与噪声、共享材质缓存；跟随原块版本更新和释放。两个兼容模块不改游戏 Tile 或原始地形位图。

当前版本已按用户授权安装到 1.02；隔离实例仍使用独立应用身份和资源副本，不触碰正式存档。全场实体常驻、瞬移同步补块以及大图光照仍有性能成本，不宣称无限地图或任意剧情兼容。

## 补丁边界

`Grafon` 因增加字段和绘图分支而整类重编译。`Location` 只换构造方法，`Camera` 只换 `calc` / `setZoom`，`Game` 只换 `save`；`MainFE` 保持原生清单加载器的字节。FFDec 的 ActionScript 反编译后整类回编会改变其他方法，因此上述四个方法只移植经过定位的 P-code（SWF 方法指令）。官方 FFDec CLI 负责写入 SWF；Python 仅生成源码、指令文本和读取审计数据。

构建核对 4665 个无关具名方法及初始化方法的指令字节保持一致，并确认四个必需方法确实变化。该检查不能代替玩法验证，也不代表所有匿名函数、资源和玩法均已全面审计。

尺寸暂限定为 48..512 × 25..256 格以防异常输入；上限是输入保护值，不是已验证容量承诺。实际样片为 192×60。下一阶段仍应先扩充运行压力与原版交互测试，再接编辑器。
