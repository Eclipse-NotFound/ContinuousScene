# ContinuousScene：镜头移动性能退化对照审查与可执行优化方案

> **文件标识**：`mods/ContinuousScene/design/stutter-optimization-plan-20261103.md`  
> **编制日期**：2026-11-03  
> **当前基线**：宿主 `pfe.swf` (A9B39CC7)、CS 0.9.6 (F16890C9)、`scene.xml` (1CEA74E2)  
> **适用环境**：马哈顿废墟、轻机枪（LMG）、大窗口（2048×1123 scale=1）、RV/WallBlend/光暗效果关闭  
> **状态**：**Git 历史审查与优化方案定稿，处于待阶段化执行状态**

## 1. 背景与问题定义

用户反馈：**ContinuousScene 模组在镜头移动的性能表现相比此前表现最好的版本出现明显退化**。在马哈顿废墟、大窗口全屏展开、持轻机枪探索/开火移动时，镜头画面发生显著卡顿与帧跳动。

### 1.1 真实游玩现场采样（Session 1793689524405-11a6）
经严格筛选排除加载峰值与菜单暂停（保留合格有效时长 196.364 秒、共 5143 帧）：
- **事件平均到达率**：26.19 FPS（低于 30fps 基准，移动窗口进一步跌至 25.84 FPS）；
- **严重卡顿（>100ms 帧）**：196 秒内发生 **38 次**（平均每分钟高达 **11.61 次**）；
- **最大单帧间隔**：**242ms**（造成接近 1/4 秒的严重视觉冻结）；
- **同路回走开火开销**：在无新区块生成的已驻留区域，轻机枪开火回走比不开火回走**整帧平均耗时慢约 8ms**（36.66ms → 44.78ms，P95 45ms → 58ms）。

### 2.2 核心退化根因深度剖析

#### 根因 1：CS 0.9.5 物体剔除的“全量线性轮询”吞噬帧时间（已实证）
- **代码位置**：`src/SceneObjectCulling.as:43-69`
- **机制剖析**：为避免修改游戏原生对象的 `visible` 属性（破坏 `UnitSpectre` 隐身逻辑），0.9.5 在每个子对象外包装了一层 `Sprite`。但在更新时，它在每帧对 `visObjs` 层的所有子节点执行 `while(i < layer.numChildren)` 遍历，频繁调用 `getChildAt(i)`、哈希表查找以及 `child.getBounds(w.visual)`。
- **实证数据**：在 2026-11-03 隔离诊断第 3 轮（同进程 8 窗口 ABBA 交替开关剔除测试）中：
  - **关闭剔除**：CS 模组内部处理时间仅为 **0.26ms ~ 0.39ms**；
  - **开启剔除**：CS 模组内部处理时间飙升至 **6.31ms ~ 7.63ms**！
  - **结论**：在 30fps（每帧仅 33.3ms）的严苛预算下，一个原本用于降低渲染负担的剔除模块，自身仅 AS3 遍历开销就吃掉了 **20%~23%** 的整帧时间！当玩家移动镜头时，物体的屏幕相对位置持续剧烈变动，触发大量的属性赋值与边界判定，成为镜头移动卡顿的首要真凶。

#### 根因 2：宿主预绘预算上限膨胀（48ms）与阻塞执行（代码级确证）
- **代码位置**：宿主 `Grafon.as:2378` (`sceneEnsureUpcoming`) 及 `:3268` (`sceneAdvanceWarm`)
- **机制剖析**：
  1. 宿主补丁将预绘时间预算设为 2~48ms。48ms 是历史极端平移测试（80px/帧）遗留下来的数值，它**严重背离了 30fps 下整帧剩余时间通常只有 5~15ms 的现实**。
  2. `sceneAdvanceWarm` 仅在步骤之间做检查（`if(getTimer() - start >= budget)`）。然而单个背景层绘制、复杂地形滤镜或底图步骤（`drawKusok`）往往耗时巨大且不可中途中断，单步越界即导致单帧预绘耗时突破 30~50ms。
  3. 叠加游戏本身的逻辑与物理更新，整帧耗时必然直奔 100ms 以上，直接产生真实游玩中观察到的 38 次 >100ms 慢帧。

#### 根因 3：轻机枪移动射击诱发“预绘相交取消 → 视口强行补画”恶性风暴（机制确证）
- **代码位置**：宿主 `Grafon.as:1085` (`sceneApply`)、`:3046` (`sceneCancelWarm`)、`:56` (`sceneRender`)
- **机制剖析**：
  1. 玩家手持轻机枪（高射速）移动探索时，连续射出的子弹击中前方墙面，调用 `sceneApply` 在世界中记录弹痕（decal）。
  2. `sceneApply` 会计算受影响范围（带有 80px 的外扩），并对相交的正在异步预绘区块调用 `sceneCancelWarm(affected)`。
  3. 预绘作业被无情取消、已经画好的中间数据被 `dispose()` 丢弃。
  4. 当玩家镜头推入该区域时，原本应就绪的区块发生视口 miss，宿主只能调用 `sceneRender` **同步强行完整重绘**！
  5. 结果：**异步预绘前功尽弃，同步绘制阻塞主线程**，造成同路开火比不开火陡增约 8ms 且伴随瞬间冻结。

#### 根因 4：历史弹痕（Marks）无索引全量线性扫描随时间劣化（代码确证）
- **代码位置**：宿主 `Grafon.as:1161` (`sceneRestoreMarks`) 与 `:1085` (`sceneApply`)
- **机制剖析**：
  1. 每次区块重建或应用弹痕时，系统遍历全部 `sceneMarks` 数组。
  2. 当前虽有相交矩形剪枝，但由于**缺乏空间索引**，算法复杂度为 $O(N)$（$N$ 为全图已产生的所有弹痕数）。
  3. 轻机枪连续射击产生数以百计的弹痕，使得遍历开销单调攀升，导致游戏时间越长、战斗越激烈，镜头移动越发卡顿。

#### 根因 5：为什么此前的基准测试探针未测出退化？
- 2026-11-02 的 `camera-regression-bisect-20261102.md` 探针测试采用了 **非战斗纯走动、已驻留路径往返、短路线、无轻机枪射击、无动态碰撞敌人** 的受控环境。
- 在那种纯净环境下，没有弹痕 Cancel 风暴、没有大批动态实体触发物体剔除属性跳动、没有深层探索冷块超载。因此探针得出了“v96 比 v93 略快”的假象。真实游玩场景的复杂性彻底击穿了探针的覆盖边界。

## 3. 优化目标与工程准则

### 3.1 核心量化目标
1. **消除 >100ms 异常长帧**：在马哈顿废墟自然探索与轻机枪射击测试中，>100ms 长帧频次降低 **60% 以上**（由当前的 ~11.6 次/分压制到 <4 次/分）。
2. **压低帧耗时尾部**：P95 帧间隔从 ~58-65ms 下降至 **<42ms**（降幅达 25%~30%），恢复到 0.9.3 的流畅移动水准。
3. **压制 CS 模组自身开销**：将 `SceneObjectCulling` 与 CS 模组的帧处理时间从当前的 **6~8ms 压缩至 <0.8ms**。
4. **消除开火额外惩罚**：将已驻留区轻机枪开火与不开火的帧时差从 8ms 收敛至 **<2ms**。

### 3.2 严格红线与防踩坑原则
- **坚决避免“减分配≠减帧时”的无效劳动**：不再重复尝试已被实测否定的单独环境键缓存、纯垃圾对象清理等无帧收益路线。
- **坚决不复活已被证伪的劣化方案**：
  - 严禁炮塔同帧守卫（Phase 3 负结果已确证）；
  - 严禁全景逐帧低分辨率合成、整景低清缓存（严重拖慢帧率且画质劣化）；
  - 严禁每帧动态切换 `stage.quality`。
- **严守正确性红线**：
  - 保持原生 `visible` 语义所有权，严禁擅自改写原生实体可见性（避免 `UnitSpectre` 隐身失效）；
  - 维持 SATS 战术截图的完整保真度（截图时透明暂停剔除）；
  - 保证屏外命中与真实弹道判定正确，杜绝地图视觉空洞或拼缝。

## 4. 分阶段可执行优化实施方案

实施策略遵循：**先模组层低风险速赢，再宿主层解耦攻坚，最后空间索引根治；每阶段独立候选、独立双臂验证、独立可回滚**。

```
[Phase 0: 基线固化与深层路线建立]
                ↓
[Phase 1: 增量事件化物体剔除 (event-tracked-1)] → 纯模组层，立即斩断 7ms 脚本开销
                ↓
[Phase 2: 弹痕预绘解耦与非破坏性缓冲]         → 宿主改动，根除开火 Cancel-Force 风暴
                ↓
[Phase 3: 自适应余量预绘与震屏解耦]           → 宿主改动，根除 48ms 越界引发的 >100ms 长帧
                ↓
[Phase 4: 弹痕二维空间网格索引]               → 宿主改动，根治探索战斗中后期的 O(N) 累积退化
                ↓
[正确性保障: Bullet 空间候选集解耦]           → 修复 sceneCU 视口依赖，确保屏外命中无缺陷
```

---

### 4.1 Phase 0：基线指纹锁定与端到端诊断夹具加固
- **执行时间**：即刻完成
- **工作目标**：
  1. 固化正式输入指纹：根 `pfe.swf` (A9B39CC7)、CS 0.9.6 (F16890C9)、`scene.xml` (1CEA74E2)。
  2. 确立一条**合格的深层探索与开火路线**：涵盖马哈顿废墟已驻留区域往返、穿越复杂障碍进入 2 个以上全新未生成区块、包含跳跃与高低落差，全程无撞墙停滞。
  3. 在测试探针中注入关键诊断指标：
     - `cancelCount` / `cancelWorkMs`（被取消的预绘作业与浪费工时）；
     - `syncRenderCount` / `syncRenderMs`（视口强行补画次数与耗时）；
     - `stepMs` / `maxStepMs`（单步预绘耗时与峰值）；
     - `cullingVisits` / `boundsReads`（剔除遍历节点数与 bounds 读取次数）。

### 4.2 Phase 1：增量事件驱动物体剔除（SceneObjectCulling event-tracked-1）
- **改动范围**：模组源码 `src/SceneObjectCulling.as`、`src/SceneCullEntry.as`、`src/ContinuousSceneMod.as`（纯模组层，无须改动宿主）。
- **技术设计**：
  1. **事件驱动增删跟踪**：
     - 在 `bind()` 时给 `visObjs` 容器监听 Flash 原生 `Event.ADDED` 与 `Event.REMOVED`。
     - 维护 `added` 与 `removed` 队列，不再每帧主动调用 `layer.getChildAt(i)` 发现新节点。
  2. **脏标记与属性缓存**：
     - 引入专用结构 `SceneCullEntry` 缓存 `(x, y, sx, sy, rotation)` 以及局部的 `(left, right, top, bottom)` 相对边界。
     - 只有当相机视口矩形发生变化，或者物体的坐标/缩放发生实质改变时，才进行视口相交判定；否则直接跳过（`continue`）。
     - 仅当对象的 `hidden` 状态发生翻转时，才写入一次 `wrapper.visible`（消除无谓的 DOM 属性写入）。
  3. **边界读取优化**：
     - 初次测量后缓存相对边界，动态对象仅在 `sx!=e.sx || sy!=e.sy || rot!=e.rotation` 时才重新调用昂贵的 `getBounds(visual)`。
  4. **兼容性保障**：
     - 完整保留 `suspendForCapture()` 与 `resumeFromCapture()`，保障 SATS 截图时全量可见；
     - `w.gg.teleObj` 念力抓取对象与 `lurk` 潜伏箱始终排除在包装层外，直挂原父级。
- **预期收益**：
  - 将 `SceneObjectCulling.update` 的每帧耗时从 **6~8ms 直降至 0.2~0.4ms**，整帧瞬减约 6~7ms 负载。
- **验证门禁**：
  - 运行 `src/tests/SceneCullingChecks.as` 全部 24 项单元断言（包括可见性归属、念力抓取、包装层还原、SATS截图恢复等）通过；
  - 运行 `stutter_opt.py run stutter-culling-opt` 验证 CS 内部处理时间稳定在 <0.5ms。

---

### 4.3 Phase 2：弹痕解耦预绘与非破坏性作业缓冲（彻底根治移动开火卡顿）
- **改动范围**：宿主补丁 `fe.graph.Grafon`（方法：`sceneApply`、`sceneCancelWarm`、`sceneAdvanceWarm`）
- **技术设计**：
  1. **区分操作类型**：
     - 审查传入 `sceneApply` 的 `kind`：区分 `kind == "paint"` / `"decal"`（纯弹痕贴图）与破坏性地形改动（如爆炸破坏 `drawKusok`、水体变动）。
  2. **非破坏性弹痕待应用缓冲（Pending Marks）**：
     - 当轻机枪弹痕落在正在异步预绘的区块（`sceneWarmJob`）相交范围内时：
       - **旧逻辑**：直接调用 `this.sceneCancelWarm(affected)` 销毁整个作业并释放 BitmapData。
       - **新逻辑**：如果该变更仅为普通 decal/paint，**严禁取消预绘作业**！将该弹痕记录推入该 job 的 `pendingMarks` 队列中。
  3. **预绘完成时合并增量**：
     - 当 `sceneAdvanceWarm` 完成所有底图与材质绘制步骤、即将把区块交还给驻留集合之前，检查并顺序重放 `pendingMarks`，利用已有图章逻辑一次性盖上弹痕。
  4. **破坏性修改维持安全取消**：
     - 若为真正的墙壁破碎或实体破坏，维持原有的 `sceneCancelWarm` 机制，保证画面逻辑绝对一致。
- **预期收益**：
  - 轻机枪连续开火射击移动时，预绘作业取消率从大量 Cancel 直降为 **0 次 Cancel**。
  - 彻底杜绝视口强行补画（`sceneRender`），同路开火耗时恢复到与不开火基本一致（消除 8ms 惩罚）。
- **验证门禁**：
  - 持续轻机枪射击前推测试，断言 `cancelCount == 0`，视口 `syncRenderCount == 0`；
  - 像素比对验证待应用弹痕与原生即时弹痕在最终画面的位置、透明度、混合模式完全一致。

---

### 4.4 Phase 3：预绘自适应帧余量调度与相机预测解耦（根除 >100ms 慢帧）
- **改动范围**：宿主补丁 `fe.graph.Grafon`（方法：`sceneEnsureUpcoming`、`sceneAdvanceWarm`）
- **技术设计**：
  1. **自适应帧余量算法替代固定 48ms 预算**：
     - 废弃硬编码的 `48ms` 激进上限。
     - 引入自适应动态预算计算公式：
       $$\text{budget} = \text{Math.max}(2, \text{Math.min}(16, 33.3 - \text{lastFrameElapsed} - 4))$$
     - 若当前帧由于复杂 AI 或物理运算已经耗时较多（如 `lastFrameElapsed >= 25ms`），则预绘预算收紧到保底的 2ms；
     - 仅当当前帧轻负载时，才允许消耗至多 16ms 进行预绘。坚决不允许预绘单次执行占满 48ms。
  2. **单步耗时防穿透守卫**：
     - 在 `sceneAdvanceWarm` 的每个分步执行前后做时间采样；若单步耗时已经耗尽预算，立即主动退出（`return`），等待下一帧继续，避免连续多步在同帧堆叠。
  3. **预测位移剥离后坐力震屏**：
     - 在 `sceneEnsureUpcoming` 计算相机未来方向时：
       ```actionscript
       // 剥离 World.quake 武器后坐力震颤分量，提取真实的相机平移速度向量
       var pureVx:Number = -camera.vx; // 不叠加 quakeX
       var pureVy:Number = -camera.vy; // 不叠加 quakeY
       ```
     - 避免武器高频震屏把预绘视口拉偏、导致在非移动方向上白白浪费预绘资源。
- **预期收益**：
  - 预绘再也不会将正常帧拉扯为 >100ms 的严重掉帧；长帧频次下降 60% 以上。
- **验证门禁**：
  - 记录 3000 帧完整区间，统计 `maxStepMs <= 16ms`，预绘阶段诱发的 >100ms 帧降至 0。

### 4.5 Phase 4：二维空间网格索引彻底消除弹痕线性扫描（长局性能保障）
- **改动范围**：宿主补丁 `fe.graph.Grafon`（字段及方法：`sceneMarksGrid`、`sceneRestoreMarks`、`sceneApply`）
- **技术设计**：
  1. **空间网格哈希结构**：
     - 宿主中新增以区块坐标为键的二维索引表：
       $$\text{sceneMarksGrid}[\text{cy} \times \text{GRID\_STRIDE} + \text{cx}] \rightarrow \text{Vector.<DecalMark>}$$
  2. **写入命中定向索引**：
     - 当子弹击中时，根据弹痕的世界坐标 `(X, Y)` 计算其所覆盖的 1~2 个相关地块网格 `(cx, cy)`，直接挂载在对应网格的列表中，并保留全局自增序号 `seq`。
  3. **还原查询由 $O(N)$ 降至 $O(1)$**：
     - `sceneRestoreMarks` 重绘某区块时，直接提取该区块坐标及其相邻 gutter 区域的弹痕列表，不再对全图成百上千个历史 marks 遍历。
- **预期收益**：
  - 彻底根除游戏探索时间越长、战斗越激烈卡顿越严重的“时间滚雪球”退化。
- **验证门禁**：
  - 注入 1000 个弹痕后进行长距离平移测试，断言 `markScanned` 计数下降 90% 以上，帧耗时无统计学抬升。

### 4.6 正确性前置修复：Bullet 碰撞候选集脱离镜头视口（宿主修复）
- **改动范围**：宿主补丁 `fe.weapon.Bullet.run` 与 `fe.graph.Grafon.sceneTick`
- **问题分析**：A9B3 宿主在 `Grafon.sceneTick` 中把视口 ±500px 内的单位塞进 `visual.root["sceneCU"]`，供子弹碰撞判断。这导致普通房间、离开大场景或超远射程子弹无法击中屏外目标，严重违背游戏原生战斗机制。
- **修复方案**：
  1. 子弹碰撞候选必须依据**子弹自身当前的位移扫掠段（Sweep AABB）**，而不是根据玩家相机的视口！
  2. 当子弹无目标时，优先使用真实世界空间网格检索；在网格未就绪或无法证明局部完整时，安全回退到当前 `loc.units` 全量遍历，坚决不用相机的 `sceneCU`。
  3. 退出大场景时，在 `sceneTick` 中彻底清空 `visual.root["sceneCU"]`，防止跨地图数据污染。
- **验证门禁**：
  - 运行 `src/tests/SceneOffscreenHitChecks.as`，验证屏外自然休眠敌人受到真实伤害并正确唤醒，断言 `offscreen-hit-first-real-bullet-damages` 与 `offscreen-hit-next-activity-awake` 全部通过。
