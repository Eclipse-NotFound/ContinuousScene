# ContinuousScene：轻机枪移动与探索卡顿优化执行方案

2026-11-03。适用：根宿主 A9B39CC7、CS 0.9.6 F16890C9，马哈顿废墟、大窗口、RV/WB/LAD 效果关闭。状态：**调查与方案完成，优化尚未实施、未部署**。完整证据及不能外推的条件见 [调查报告](../knowledge/experiments/stutter-investigation-20261103.md)。本方案替代旧 combat-motion-optimization-plan 的后续优先级，旧文件保留其历史。

## 1. 要解决什么

目标分别是：已驻留区轻机枪射击时减少连续掉帧；首次探索时减少短时严重卡顿；保持角色位置、碰撞、命中和画面正确。优先减少真正的完整帧长尾，不以 helper 计时或分配数量下降替代玩家体验。

已有依据：真实游玩 196 秒有 38 次 >100ms 长帧；两轮同路回走开火比未开火约慢 8ms；本轮未见呈现拆建风暴或成批唤醒。剔除全扫描有明确局部开销，但停用后的整帧改善不全同向。深层自然探索尚无包含取消作业事件的准确复现。

## 2. 实施顺序

| 顺序 | 交付 | 为什么先做 | 完成／转向条件 |
|---|---|---|---|
| 0 | 当前产品的来源清单、合格路线与细分计数 | 防止基于旧源码改掉已有修复，或把堵墙/离屏当探索 | 指纹固定；实际 LMG、玩家屏内、真实位移、新块事件均可核对 |
| 1 | 将物体剔除改为局部增量更新的独立候选 | 当前有同进程开关的脚本成本证据，纯模组层、回滚小 | 局部成本下降且整帧配对有收益；否则保持现状 |
| 2 | 绘制取消原因归因；普通弹痕不再废掉整块预绘 | 直接针对开火叠加首次探索的潜在峰值 | 先证明取消链发生且耗时有分量，再做候选 |
| 3 | 分帧绘制按整帧余量及到达期限调度 | 当前最多 48ms 预算本身可超一帧；同步补画仍在 | 长帧下降且 misses/forced、缺块率没有恶化 |
| 4 | 弹痕历史与驻留块的空间查询索引 | 避免探索/战斗越久扫描越多 | 有长局增长证据；保持像素、顺序和存档恢复 |
| 正确性前置 | 核对并修复碰撞候选集合的空间/生命周期边界 | 当前按镜头筛目标，屏外命中不能被舍弃 | 屏外/跨房/普通房间命中通过，才进入任何发布验收 |
| 条件触发 | 对确与长帧相关的回收源做组合治理 | 真实及诊断均有回收相关线索，旧单项减垃圾未改善帧时 | 只在帧长尾下降时采用；不再凭分配计数发布 |

每个候选单独构建、单独证据、独立回滚，不一次捆绑全部优化。这里的顺序不代表收益已经验证。

## 3. 第一批具体工作

### 3.1 固定基线并补齐诊断（前置，约半日至一日工作量）

1. 保存本轮正式 13 模组、资源、配置及描述符清单；从准确 A9B3 产物导出需要修改的方法，逐方法核对。保留已有 A2、48ms、SATS、区域染色、鼹鼠与联机接点。不要把旧 GrafonChunks.as.inc 整包重编译后覆盖宿主。
2. 在现有诊断探针上加**测试专用**指标：`sceneTick`、warm step 类别/耗时、cancel 次数/原因/已废弃毫秒、强制绘图次数/耗时、命中更新遍历块数/命中块数、历史痕迹扫描/实际应用数量。区分地形破坏、水变化、普通 decal/paint。只累计内存计数，测量后写盘。
3. 用当前实际数据构建可通行路线，至少含已驻留往返和两个不同新区域、横移与一次上下层移动。先查地图可通行，再让原生移动/跳跃执行；测试结束校验实际位移与新块数。堵墙、没出膛、离屏、换枪未完、加载错误均不算相应场景合格。
4. 划分不射击、仅玩家 LMG、同屏真实敌人交火；保留射速、敌人行为与原生物理。记录自然单位类别/数量及活动数，不能把同布局种子称作完全相同战斗。
5. 角色“跳动”先同时看完整 dt、逻辑位置、显示位置及屏幕投影。只在普通帧也出现位置错相时另开镜头同步修复，不先改游戏 tick 或插值来遮住长帧。

产物：可重复路线、同版本基线统计、每类慢帧事件表。门槛是“能判别假设”，不是再跑一套所有模组的完整矩阵。

### 3.2 优先候选：增量物体剔除（约一至两日）

改动位置：`src/SceneObjectCulling.as`，必要时在 `ContinuousSceneMod.as` 增加只读计数。

- 保留当前包装层 visible 的职责；不接管对象自己的 visible/alpha，不摘除追击者或弹体的逻辑对象。
- 静态根按世界格登记；相机跨格或 viewport 尺寸改变时，只处理新进入/离开的格。停留在同一范围时不遍历整层。
- 动态单位、弹体、可移动物体单列，只更新它们及刚变换/增删的根。已隐身、潜地、空边界与动画边界变化保持保守可见。不能把初次 getBounds 永久当作动画的准确边界。
- 通过增删事件/受控脏标记维护登记；处理层重建、SATS 暂挂、念力重新挂父层、Location 替换及回退清理。低频审计漏挂对象即可，不再每帧重新发现所有节点。
- 候选目标：把静态全量遍历降为视口边缘变化＋动态对象更新。局部目标可用“比自身基线下降至少 60%”筛选，最终仍按整帧门禁判断。

不直接默认关闭剔除：第三轮存在反向整帧配对，关闭还会增加屏外原生渲染。若增量版本没带来稳定完整帧收益，则停止，不用低脚本计时强行部署。

### 3.3 先测再改：避免弹痕废掉预绘（约一至两日，条件触发）

改动范围：当前宿主 `Grafon.sceneApply / sceneCancelWarm / sceneAdvanceWarm / sceneRestoreMarks`，模组目录内构建候选。

执行前要求：在自然新区域 LMG 路线上观测到 `cancel → 重做 → miss/force`，并量化它占慢帧的程度。若取消很少或成本不显著，先转下一条，不凭源码猜测发布。

实现方向：区分**改变地形/遮挡的数据**与**仅叠加画面痕迹的数据**。普通 decal 不取消底图作业，改为带顺序号的待应用痕迹；所有区域风格组完成后、进入显示树前，将作业期间新增的相交痕迹按原顺序补上。保留原随机 stamp 和混合模式。已经完成的风格组同样需要补增量，不能只对最后一组补画。

地形破坏、影响阴影/材质的变化继续使有关底图失效；若无法证明某类操作可叠加，保持原取消回退。多次命中同一位置不能丢、重放或改序。提交前核对地图/区域/地形代次，作业过期不得挂进新场景。

验收：取消废弃工作显著减少，首次可见块仍完整，弹痕与破坏像素/存档恢复一致；玩家前方同墙持续扫射、爆炸破墙和切图取消都要覆盖。

## 4. 第二批工作

### 4.1 让预绘使用可用的帧时间，而非只提高上限

当前的 48ms 是为历史 80px/帧极端平移增加吞吐量，不能直接当正常 30fps 下的合理每帧预算。也不能只将 48 改小：这会把债务推到同步补画。

- 测量模拟/模组处理及此前完整间隔，采用平滑、保守的整帧余量估计；持续超载时不得继续无条件叠加大份预绘。
- 当前实际视口仍包括震屏；**预测来向使用去掉震屏的相机位移和玩家速度**，避免震动改变预绘方向与预算。
- 优先级按预计进入视口的时间排序，并考虑每块剩余成本；近处缺口优先，保留短暂反向和纵向落差的预备范围，不能盲目扩大常驻环。
- 在已有步骤之间继续拆分确认过大的材料/背景/历史重放工作；保留原绘图原点及绘制顺序。单次原生 draw/filter 无法任意中断时，先降低每步输入量并做像素验证，不能声称有严格毫秒上限。
- 同步兜底先保留以避免可见空洞，目标是通过提前准备减少其触发。普通走动、冲刺、掉落、看远处和折返分别验收。

### 4.2 空间索引解决增长，不重做已有弹痕剪枝

- `sceneApply`：根据 affected 计算相交块坐标，直接查 `sceneChunks`，不逐个扫描所有驻留块。包含 gutter、爆炸、越界坐标及多块横跨。
- 历史 marks：按块/区域登记索引，保留全局顺序号；重绘查询相交候选并按原顺序重放。旧存档首次恢复时建立索引；存档的权威数据和随机 stamp 保持兼容。
- 呈现绑定：仅绑定新增/重绘/移除块，视口显示变化不应触发所有驻留块的资格重查；先以计数确认该路径有足够成本再实施。
- 只在实测内存压力和驻留规模确实成为问题时另做有上限的位图驻留方案。驱逐会带来回头重绘、SATS和永久痕迹恢复风险，不列为首批默认改动。

### 4.3 碰撞候选集合必须脱离镜头边界

当前 `sceneCU` 不含完整屏外目标；旧屏外测试并不覆盖 A9B3。先加当前正式宿主的屏外自然 Bullet 命中、穿透、爆炸/光束差异、进出连续地图和普通房间回归。

设计以 Location＋生成代次＋逻辑帧为资格，按**弹体当前子步／扫掠范围**查世界空间格，纳入单位完整 AABB。保留原 targetObj、阵营、dopTest、命中顺序和穿透语义。运动、传送、出生、移除应更新索引；同一 tick 中先后运动的目标不能因旧位置漏查。无法证明索引当前有效时回退到该 Location 的全量单位，不能继续使用另一场景/旧帧/镜头内列表。

先用小型正确性夹具定边界，再讨论提速。不得通过减少射速、屏外弹体、追击者或命中集合来达标。

### 4.4 GC 与原生呈现：保留有条件路线

真实记录及前两轮同帧内存回落与长帧高度共现；第三轮大量额外长帧没有同样回落，环境与渲染仍需区分。采样诊断与最终计时分开，标明单位、弹体、特效和对象寿命，不能将触发 GC 的栈当作分配来源或独占原因。

已有单独区域键缓存、炮塔同帧守卫、wholeworld/低分辨率缓存和逐帧画质切换均有负结果；不重跑同实现。只有减少反复预绘/全量扫描等实际工作后，若仍剩稳定回收长帧，才用当前组合做有指纹的组合候选。其它模组的改动由其授权范围内的维护任务完成。

## 5. 验收与停止条件

以下是**拟定工程验收目标，尚未达到**：

- 同一产品指纹、窗口、路线与负载，至少三组成对顺序交错测试；两个独立进程，测量期 30fps。全部输出完整间隔，同时给切换帧敏感性统计；不能只挑最快一窗或剔除 GC 帧。
- 优先候选在对应场景 P95 下降至少 15–20%，且 >100ms 次数/分钟下降约 50%；若基线长帧太少，延长同一路线直到样本足够，不用零星几帧作百分比结论。
- 普通不射击移动不能持续退化超过约 5%；新块 misses/forced 不因减预算升高。内存驻留/峰值必须注明，不能靠无界缓存换来短时数字。
- 游戏完整性：实际出膛、同屏敌方攻击、屏外命中、追击、潜伏/隐身、门/念力、SATS、爆炸破坏、切图与存档恢复按改动范围覆盖；没有触及的机制复用匹配指纹的已有证据。
- 视觉单独检查原生画面、角色与地形相对运动、拼缝和半透明像素，计时中不截图。阶段目标保持现有画质，不默认用降低动画频率或隐藏可见对象过关。
- 若只减少 helper 毫秒/分配量而整帧无稳定收益，候选不部署。若只有某特定速度/地图受益，限定适用条件，不宣布总体解决。

所有运行先登记、唯一存储、默认静音后台。性能证据受其它负载污染时降级为观察，继续必要功能验证，不干预玩家或其它会话进程。

通过对应门禁后才沿持续授权备份并部署已验的同一产物，重读指纹；宿主仅替换目标方法。失败只回滚本次仍然在位的文件，保留并发新版本。**本轮没有部署、没有后台继续执行承诺。**
