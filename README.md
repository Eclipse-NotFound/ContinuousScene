# ContinuousScene：连续大场景 0.4.0

当前阶段只做大场景运行，地图编辑暂缓。游戏入口使用 **12 个原版工厂房间组成的连续测试场景，192×75 格，即 7680×3000 像素**，保留 444 个物件标记和 603 个背景装饰。场景内没有换房线，玩家、敌人和弹体共用同一个坐标空间。它不是原版随机工厂完整剧情的复刻。

## 游戏内入口

保存并正常重启根目录 1.02 游戏后，打开哔哔小马的 **信息页**，点击顶部的 **大场景 · 工厂**；进入后同一按钮变成 **大场景 · 返回基地**。入口沿用原版旅行限制，受伤、负重或剧情条件不允许旅行时不会强制传送。

正式场景沿用当前角色，按工厂数据生成原版敌人，不自动开新档或注入探针专用敌人。它是运行测试地图，还不是完整关卡。RealisticVision 与 WallBlend 的显示效果已适配，配置与玩家已有选择保持。

0.4 修复部分墙边反复出现黑块：第二背景层此前漏减画面块原点，管道、栅栏等重复画到了各块相同位置。现在与其他世界图层使用一致的坐标换算。保留 0.3.1 的菜单暂停点击修复。过程、像素对照和性能限制见 [工厂接入记录](knowledge/experiments/factory-v04-20261015.md)。

## 独立试玩

双击本目录的 **[Start-Scene.cmd](Start-Scene.cmd)** 可打开旧版稀疏走廊，用于独立战斗回归；它与正式入口的工厂不同。约 30 秒完成启动与整图预绘后进入独立测试窗口；每次启动创建一局新的测试游戏。A/D 移动、空格跳跃、鼠标左键攻击、R 换弹、I 打开物品栏，沿用原版操作。长走廊中放了三只原版鼠怪。关闭游戏窗口退出。

这是简化的运行测试场景：有长走廊、上层平台、竖向通道和混凝土破坏目标。独立试玩额外放置三只鼠怪；正式游戏入口不注入这组三只测试敌人。手动入口与自动测试共用独立应用身份，同一时间只开一个。

隔离产物位于 `build/runtime/`，测试存储为 `%APPDATA%/pfe-modsettings-continuous-scene/Local Store/`。自动验证不读写玩家正式存档；当前玩家游戏未被关闭。生产模组与测试驱动分离，测试驱动没有安装到正式加载清单。

## 现在做到哪里

一个扩大的 `Location`（原版的房间运行对象）承载整个场景。**进入时预绘整张地图，游玩中全部保留**；工厂的 240 个画面块只用于组织像素，没有内部房间切换，也不随镜头卸载。玩家、敌人、子弹和碰撞始终共用全场空间。地形与墙面覆盖层各自共用像素存储，局部弹痕只刷新附近块；原版存档保存地形变化和破坏痕迹。

原版敌人 AI、子弹命中和碰撞方法继续执行。0.3 还让 RealisticVision 在需要判断可见单位时才复制整图视野快照。验证与性能对照见 [0.3 预绘记录](knowledge/experiments/preload-v03-20261014.md)，实现边界见 [运行设计](design/runtime.md)。

当前限制：

- 工厂检查覆盖全部 12 区截图、原版通道步行与追击/子弹、基地往返及存读档；尚未逐个验收所有门、升降台和随机敌人标记。当前已启用模组组合通过测试；联机、更大地图与长时间游玩未验收。
- 历史0.3走廊长距离行走中位55ms、p95 73ms、p99 87ms；1699帧没有生成地形块，**仍未稳定达到30帧**。独立后台测试显式固定进程策略，正式启动器未改，实际试玩帧率仍需观察。
- 以上 0.3 的 13.5 秒进图、1.8–3.1GB 峰值仅属于旧走廊，不能用于密集工厂。工厂各轮点击到可操作约 55–81 秒，最终组合为54.7秒；31个短通道行走帧中位89ms。包含逐层对照、往返及读档的诊断进程Private峰值6501MB，不能当成正常稳态内存。首次加载和内存仍有明显成本，未达到稳定30帧。完整数据见工厂记录。
- 全场景格子、实体和地形画面常驻；尚未做远处实体休眠或场景数据按需读盘。
- 大场景固定原倍率，暂时禁用原版“缩放到整间房”模式。
- 工厂统一使用原版工厂基础色调和背景；区域元数据保留了源房间色调，但暂未逐区应用。支线后房、跨层剧情及原版随机工厂生成器未整体移植。信息页地图缩略图未扩展，本轮修复针对游玩画面。
- 存读档沿用原版检查点语义；本版补齐大场景地形破坏与弹痕的跨读档保留，并验证新旧存档交替加载。
- SATS 画面覆盖已验证；完整战术操作、水体变化、动态门、剧情、地图界面、所有武器和不同窗口尺寸未逐项验证。
- 地图编辑器暂缓。`build/factory_scene.py` 从原版 `Rooms/rooms_plant.xml` 生成工厂，原始房间文件只读；测试夹具 `scene-factory.xml` / `scene-lab.xml` 可再生，不能手工编辑后当作正源。

## 构建与自动验证

在游戏根目录的 PowerShell 执行：

```powershell
& './mods/ContinuousScene/build/build.ps1' -BaseHost './pfe_before_ContinuousScene_20261014-181702.swf'
& './mods/ContinuousScene/build/test-mods.ps1' -AllMods
& './mods/ContinuousScene/build/test.ps1' -Factory -HighQoS -EvidenceName 'my-factory-run' -TimeoutSeconds 650
& 'C:/Users/hello/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' './mods/ContinuousScene/build/verify_factory.py' 'my-factory-run'
& './mods/ContinuousScene/build/test.ps1' -Quick -HighQoS -EvidenceName 'my-lab-run' -TimeoutSeconds 420
```

`-Factory` 检查工厂；不传该开关则使用旧走廊，做横向往返、跨界战斗、纵向落地、局部破坏、普通房间往返与多存档读取。`-Quick` 跳过长距离往返，`-Benchmark` 走 360 帧。默认整图预绘；`-Streaming` 仅用于旧策略对照。`-HighQoS` 只固定这次测试进程的 Windows 运行策略，不修改系统电源计划或玩家进程。使用新证据名，避免覆盖旧记录。

只改外部测试驱动用 `build/build.ps1 -ProbeOnly`；只编生产模组与驱动用 `-DriverOnly`。完整构建必须指定未经本补丁修改的已验证备份；安装后直接拿根 pfe 重复打补丁会被指纹保护拒绝。FFDec 重编译绘图类，其余改动通过官方 `-replace` 替换四个方法，最后核对 4665 个无关具名方法和初始化方法。MainFE 清单加载器保持原字节。

本轮直接测试当前安装的 RV v0.30.4-scene 和 WB 0.5.1，不重编或部署它们。旧 `compat-build.ps1` 属于历史 0.3 生产线，不能未经核对就拿它覆盖新版 WallBlend；RV HEAD 也含另一个任务的未发布接口。

## 安装与回退

0.4 用 `build/upgrade-v04.ps1 -Action Check/Install` 核对工厂、旧走廊、原版像素对照、无关字节码及当前模组指纹，只替换根 `pfe.swf`、ContinuousSceneMod 和场景 XML。`state/deployment-v04.json` 保存安装回执，`build/upgrade-v04.ps1 -Action Rollback` 可核对指纹后恢复这三个文件到此前 0.3.1 组合；不回写其他模组、配置或共享清单。安装或回退后均需正常重启游戏。

0.3/0.3.1 的历史回执与备份仍保留。不要直接执行旧整体回退：WallBlend 后来已独立升级，它会被旧流程覆盖。回退当前版本只用 0.4 脚本。

发布前跑候选完整生命周期、原版绘制对照及视觉模组混装检查，安装后再用正式路径原生启动验证。脚本遇当前宿主或其他模组字节变化会停止，需要核对并重跑受影响组合，不使用旧产物覆盖他人的新版本。

当前工具位于 `mods/Sandevistan/build/tools/`，仅作为共享只读工具链使用；Java 与 Python 路径可通过构建脚本参数覆盖。构建输出和游戏资源副本不入 Git。当前版本仅匹配 2026-10-14 核对的 1.02 宿主，Steam 更新后须重新调查和适配。
