# ContinuousScene：连续大场景运行原型

当前阶段只做大场景运行，地图编辑暂缓。样片使用原版素材与战斗系统，测试地图为 **192×60 格，即 7680×2400 像素**。场景内没有换房线，玩家、敌人和弹体共用同一个坐标空间。

## 试玩

双击本目录的 **[Start-Scene.cmd](Start-Scene.cmd)**。约 20 秒后进入独立测试窗口；每次启动创建一局新的测试游戏。A/D 移动、空格跳跃、鼠标左键攻击、R 换弹、I 打开物品栏，沿用原版操作。长走廊中放了三只原版鼠怪，可测试移动和战斗。关闭游戏窗口退出。

这是简化的运行测试场景：有长走廊、上层平台、竖向通道和混凝土破坏目标。尚未制作完整关卡、任务或返回入口；死亡回到原版基地后，可关闭窗口重开样片。手动入口与自动测试共用独立应用身份，同一时间只开一个。

运行产物位于 `build/runtime/`；正式游戏 `pfe.swf`、现有模组和玩家的正式存档未修改。测试存储位于 `%APPDATA%/remains.continuousscene.dev/Local Store/`。本轮以隐藏 AIR 实例自动验证，手动窗口的交互体验尚待用户试玩。

## 现在做到哪里

一个扩大的 `Location`（原版的房间运行对象）承载整个场景；显示按 **400×400 像素**切成缓存块。镜头附近提前准备画面，远处画面释放；实体与碰撞数据继续存在，跨绘图块不切地图，不转移或重生单位。

构建改动集中在场景尺寸、镜头和地形绘制。原版敌人 AI、子弹命中和碰撞方法继续执行。自动验证结果与证据见 [运行记录](knowledge/experiments/runtime-validation-20261014.md)，实现边界见 [运行设计](design/runtime.md)。

当前限制：

- 只实测上述尺寸、少量敌人与 1280×800 窗口；更大地图、密集战斗、长时间游玩和其他模组兼容尚未验收。
- 全场景格子和实体仍在内存中，当前分块负责绘图缓存；尚未做远处实体休眠或场景数据按需读盘。
- 大场景固定原倍率，暂时禁用原版“缩放到整间房”模式。
- 存读档沿用原版检查点语义。破坏状态在画面缓存重载和本局场景往返间保留；原版存档不保存完整地形，跨读档的地形持久化尚未实现。
- 水体变化、动态门、SATS 全流程、剧情、地图界面、所有武器和不同窗口尺寸未逐项验证。
- 地图编辑器暂缓。`build/runtime/scene.xml` 是生成的测试夹具，下次完整构建会重写。

## 构建与自动验证

在游戏根目录的 PowerShell 执行：

```powershell
& './mods/ContinuousScene/build/build.ps1'
& './mods/ContinuousScene/build/test.ps1' -EvidenceName 'my-run'
```

完整测试自动进行横向长距离往返、跨边界追击与射击、纵向落地、地形破坏与缓存重载、普通房间往返、独立存档保存读取，完成后关闭自己的实例。使用 `-Quick` 跳过长距离往返，只检查战斗与场景生命周期。`-EvidenceName` 取新的英文短名，避免覆盖旧证据。

只改运行驱动时可用 `build/build.ps1 -DriverOnly`。完整构建从当前游戏 SWF 重新导出四个类；先核对固定的宿主 SHA-256，再生成补丁。FFDec 重编译绘图类，其余改动通过官方 `-replace` 命令替换四个方法，最后核对无关字节码和必需补丁。源码不依赖讨论档案中的临时导出。

当前工具位于 `mods/Sandevistan/build/tools/`，仅作为共享只读工具链使用；Java 与 Python 路径可通过构建脚本参数覆盖。构建输出和游戏资源副本不入 Git。当前版本仅匹配 2026-10-14 核对的 1.02 宿主，Steam 更新后须重新调查和适配。
