# 连续大场景运行实证：2026-10-14

用户明确先打通大场景连续加载和正常运行，编辑功能暂缓。这里验证第一阶段运行样片，不代表完整游戏或任意地图已经兼容。

## 最终结果

独立应用 `remains.continuousscene.dev`，当前 1.02 宿主的私有副本，窗口 1280×800（截图内容区 1264×761），AIR 运行。最终完整测试 **23 项断言全部通过**，驱动初始化至结束 92.985 秒。真实游戏过程由原版逻辑推进，测试通过公开控制接口移动玩家、创建原生单位和弹体；未用直接扣血代替子弹命中。

| 路径 | 观察和断言 |
|---|---|
| 加载 | 192×60 格，即 7680×2400；一个逻辑 Location |
| 横向连续移动 | 从 x=320 走到 6505.2，再回到 395.2；全程同一玩家与 Location，跨过 1920、3840、5760 三条旧尺寸边界 |
| 预绘 | 长距离往返时可见区缺块计数始终 0；缓存确实创建与淘汰，返回终点驻留 15 块 |
| 原生敌人追击 | 鼠怪从 x=1780 追到 2053.25，跨旧房间边界和 2000 像素绘图块边界，仍以玩家为目标 |
| 普通子弹 | 从 x=1780 发射，在 x≈2174 命中；敌人生命 300 → 228.04。测试 precision=0 排除随机失误，仍走原版碰撞和伤害 |
| 物理弹体 | 原生 PhisBullet 从 x=1780 运行至 2705.38，未在旧尺寸或绘图块边界消失 |
| 纵向空间 | 从 y=850 下落，穿过 1000 与 2000，最终在 y=2160 地面停止；此项启用测试无敌以排除摔伤中断 |
| 破坏 | 原版弹体破坏 C 混凝土格（原生 hp=1000、阈值=100），不修改目标格耐久或防御条件 |
| 离开缓存再回来 | 碰撞仍为空；对前景图层中缺口中心采样 alpha=0，未被重绘补回 |
| 普通地图往返 | 回基地恢复 1920×1000 原版画布；再进大场景复用原 Location，破坏状态仍在 |
| 保存读取 | 原版 saveGame(1) 记录大场景 ID；comLoad 重建 Game 后仍进入 192×60 场景，玩家存活 |

逐项记录：[result.json](evidence/full-suite/result.json)、[运行日志](evidence/full-suite/ContinuousScene.log)。图像证据：[追击](evidence/full-suite/enemy-crossing.png)、[破坏后返回](evidence/full-suite/terrain-return.png)、[读档后场景](evidence/full-suite/scene-reloaded.png)。已查看追击、破坏后返回以及长走廊画面：角色正常站立/移动，地形缺口可见，所查看区域没有可见的矩形缓存拼缝。没有因此宣称所有纹理、阴影和特效都通过图像检验。

## 性能范围

单次最终测试的稳定步行区间共 1699 个帧间隔，排除开场、转向截图附近的 32 帧，以及战斗、瞬移、保存读取阶段：

| 指标 | 毫秒 |
|---|---:|
| 中位数 | 33 |
| 95% 分位 | 48 |
| 99% 分位 | 76 |
| 最大值 | 117 |

首个整窗口重绘实验的全程 99% 分位约 314 毫秒，改成小块预绘后的早期往返约 78 毫秒；统计区间和测试版本不同，只作为优化方向的证据，不当成严格配对基准。最终版本仍有超过一帧预算的预绘开销，不能称为稳定无卡顿 30 FPS。

最终测试日志采样峰值内存约 185.71 MiB，结束约 141.20 MiB；这是 AS3 `System.totalMemoryNumber`，不等于进程总内存。采样最大驻留块数为 21，不是所有窗口尺寸的上限。测试瞬移后缺块计数增加到 44，表示同步补绘，不能与正常步行的零缺块混为一谈。原始 JSON 的 `maxChunkDrawMs=401` 实际也计入普通房间整张画布重绘，该字段不可用作单个缓存块的耗时上限。

## 调试中发现的测试条件

- 初始新档必须等资源全部载入；使用原版跳过开场选项，避免把教学动画锁控制误判为移动故障。
- 动态接口不能读 protected 的 `aiState`；原版单位没有通用 `rem()`，清理由 Location.remObj 完成，units 数组另行维护。
- `Bullet.precision=1` 并非必中，原版 accuracy 为 precision/dist。改为 0，并把发射高度放在目标碰撞框中部后，原生伤害通路通过。
- 鼠怪原生感知会暂时失去 celUnit；测试只在起始设置已暴露状态并报警，等待实际跨界且重新锁定玩家，不逐帧代替 AI 设目标。
- J 钢墙的原生伤害门槛为 1200，降低 hp 不能取消该门槛；破坏夹具改为原生 C 混凝土，沿用正常门槛和耐久。
- `allStat==1` 与目标土地身份均成立时，`t_exit` 仍可能未归零。此时再次 gotoLand 会先改目的地，但 exitLand 因旧转场未结束而拒绝启动；连续旅行必须另等 `t_exit==0`。修正后短程生命周期与最终全程检查均通过。

## 尚未覆盖

绘图缓存淘汰不会清掉本局地形，但原版 saveObjs 仅保存登记对象；目前没有跨读档保存完整破坏地形的扩展。当前存档验证只证明大场景定义、尺寸、玩家与原生保存流程可重新建立。

没有验收所有武器、SATS 全流程、水位变化、动态门、剧情与地图界面、密集敌人、长时间弹痕增长、联机、其他模组、DLC、不同窗口分辨率。实体和格子数据仍整场常驻；不是无限地图或完整的数据流式加载。编辑器未改动。

新建 `AGENT_SCOPE.md` 被工作区受保护治理文件规则拒绝，未用另一写入方式绕过；当前开发遵守根治理边界，缺口在 MEMORY 留存。自定义 Java 二进制写入尝试被自动审批拒绝后已弃用并移除，改用允许的标准 FFDec 流程完成隔离构建。
