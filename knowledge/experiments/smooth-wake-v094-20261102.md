# 2026-11-02 CS 0.9.4 分帧平滑唤醒：实现、验证与部署（优化方案 Phase 1）

## 背景与目标

用户实测"镜头移动、加载敌人实体时严重卡顿"。归因调查（见 `multi-enemy-stutter-20261101.md`、`camera-iteration-review-20261101.md`、`quality-and-dense-enemies-20261101.md`）确认：敌人并非动态创建，而是由休眠批量唤醒——同帧内多个敌人一起 `resume()` 恢复动画、恢复 `step()`、`animate()→gotoAndStop` 产生分配风暴，叠加 GC 与首帧光栅化形成尖峰。本报告实现优化方案 Phase 1（分帧平滑唤醒），纯模组层。

## 实现（src 两文件）

`NativeSceneActivity.update`（`src/NativeSceneActivity.as`）：

- **紧急唤醒（保持原即时语义）**：掉血/有目标/cut/poison（engaged 锁存）、弹道威胁重叠、stun/bind/levit/t_emerg/effects、hp<maxhp、sost!=1、player/npc/boss/gg、非敌对 fraction、inter.isMove、`scenePauseDistant=false` 功能关闭。
- **预期性唤醒（预算队列）**：仅由邻近矩形（|dx|<1900 且 |dy|<1300）或视口 +600px 边界触发的唤醒进入 `deferred` 队列，按到玩家距离升序，每帧最多授予 `wakeBudget`（默认 1）个；未授予者保持 `sleeping`（冻结 + 宿主 Location.step 跳步），下一帧重排再授予。
- 观测接口：`stats()` 增加 `budget`/`version:"smooth-wake-1"`；新增 `budget(n)` 读/写；nativeAPI 暴露 `activityBudget`。
- `ContinuousSceneMod.as`：VERSION 0.9.3→0.9.4；nativeAPI 挂接 activityBudget。

冻结配方核对：`build/generated/camera-event-fill-product-20261029/frozen-product-src` 与 `src/` 在改动前逐字一致（16 个生产编译文件哈希相同），`build.ps1 -DriverOnly` 从 src 重编，产物不含无关差异。
