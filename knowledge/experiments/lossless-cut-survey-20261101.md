# 无画面损失的优化切口普查

2026-11-01，接续用户“普查优化切口，直到不引入视觉效果损失则无优化空间”。范围是当前正式9D8662F6宿主、CS D8A68A4C和14模组组合。此前停用的LOW质量、无条件单位显隐及不完整的远敌冻结不复活。单项负结果不证明所有同类方案无效，更不能证明引擎已无无损优化空间。

## 分类与已核对边界

| 路径 | 当前证据与决定 |
|---|---|

| 地形绘制批次和缩放 | 整层缓存、GPU地形、合图、条带、屏幕像素增量等具体实现有负结果。实际默认缩放0.658333不同于2/3；相位方案真实小窗alpha不合格，禁止推广。见上一轮后继报告。 |
| 物体层裁剪与缓存 | 隐藏全物体层是诊断上界，不能部署。整层mask/scrollRect、cacheAsBitmap与屏外摘树均没有稳定足够收益。同序中性分组两窗通过离屏逐像素检查，横向/静止却有回退；额外两档大小、全图限额/附近优先缓存均完成，未得到稳定收益。 |

| 武器改装/技能武器 | 代码存在每帧参数重算、计时编码及多次对象链扫描；小样本成本尚不能推出大型背包/密集弹体的结果。未获得额外模块写入范围，不擅改或移除功能。 |
| 原版GUI/输入 | 不以关闭HUD、降低输入频率或隐藏交互为优化。鼠标命中树旧对照无收益；SATS视口截图修复保持。 |
| 内存回收与外部停顿 | 旧镜头实验多数>100ms与堆下降伴随，但并非全部。更新计时带外不等于GPU专用耗时。95%/75%阈值主动收尾均无稳定收益，P99反升；新失败同时出现Python监测长间隔，不能归给候选。 |
| 运行环境与平台API | 实测本机已有51.3.3.2并恢复51.1.3.3对照，核对自有进程实际载入DLL；没有可靠新版提速结论，不改正式运行库。桌面不支持cacheAsBitmapMatrix，Windows ANGLE有官方稳定性警告，不把这两项当现成加速开关。 |

## 快照候选的安全边界

只在TdfcRuntime内部、已有BrainState.previous时填入新的45字段，随后按原顺序previous=sample、sample=新值。当前帧与上一帧保持两个独立对象；外部公开snapshot保持新对象，玩家快照仍走原实现。ActionExecutor、PerceptionModel、SquadMind、EnemyProfile、TacticalMind和调试/夹具消费者已检查：跨帧传递的是BrainState或复制后的数值，没有保留待复用的旧snapshot引用。类别名只按对象身份缓存。调度/目标/下令顺序不变。

第一轮141个输入（真实单位及空值/缺字段/NaN/武器边界）6345个字段完全一致，公开snapshot独立身份检查通过。预热期间另开逐字段验证；其额外工作不作为性能样本。进入ABBA计时前关闭该验证。

## 失败保留

`camera-lossless-snapshot-small-r1-20261101`在预热第16轮超时，**0个正式计时块**。930对象中592个精确Box、3个Part；dead&&invis Box为0。有效已记录预热2813间隔中位35ms，但不能用于候选排名。

外部自有进程CPU监测在elapsed147.203→580.531秒之间出现433.328秒空档，随后又有137.75秒空档，CPU增量很小；AIR最终报告elapsed572664ms、phase10超时。不能据此断言具体是系统休眠、调度还是其它原因；也不能把几分钟空档算成TDFC候选卡顿。内存最低约8.6GiB可分配，没有达到中止线，没有其它AIR记录。原超时结果、日志、环境记录保留，另排r2，不延长或删除失败记录。

`camera-static-groups-small-r1-20261101`等待共享时段900秒超时，没有启动AIR；另排r2。此等待不是功能/性能失败。

## 新物体分组候选

`build/generated/camera-static-groups-v15-20261101`，探针`8E3E83C3…02A137`。只把同一原生层内连续、同空间小格的精确Box显示根放入单位变换Sprite，保持原前后顺序。不缓存像素、不停止时间轴、不改visible、不改物理/对象链。原版Box/Pt从实际vis.parent删除显示根；恢复时在组的当前位置展开尚存子节点，保留原生移除与新增，不夺回已被其它代码移动的对象。

需通过相同帧五视角RGBA逐像素及展开恢复检查后，才进入static/x/y各ABBA、每块300帧。这个隔离原型尚未证明RV/WB启用、SATS、破坏/换图/缩放兼容；即使初步更快，也须补相关检查才可部署。

## 完整帧诊断结果

沿用上一轮的独立应用ID、私有桌面、静音、真实正常世界与平台夹具。14模组保持加载，RV/WB/LAD明确关闭；布局种子4077752896不能固定所有自然单位，其类型和数量仍有波动。120fps只作容量诊断，不是原版30fps体验验收。每块首间隔-1不参与均值；其余长帧保留，计时内无截图/像素读取/磁盘写入。旧运行器`--profile`将`performanceEligible`固定为false，未改此原始标记，也不把登记“通过”写成产品性能门禁已过。

原始逐帧坐标另行回查：玩家始终(2055,1960)，没有持续传送或落地漂移；世界显示树实际横移范围320、纵移192像素，玩家投影始终在视口内。计时阶段不再写玩家坐标，不能将此夹具误解为玩家/所有单位被冻结。

快照r2共有3588有效间隔、29断言。测前137输入×45字段=6165检查通过；预热运行时5473845字段检查零失败，随后关闭验证才计时。候选平均约37次复用/帧，TDFC带1.646→1.564ms；节省局部工作不等于帧率提高。自然世界和外部非AIR负载并未完全控制，不能把整帧差值宣称为所有环境下的固定退化比例，但没有理由部署这一候选。

中性分组两窗共7176有效间隔、98断言；十视角同帧RGBA和十次展开恢复均零差异。小窗纵48.057→44.512ms，大窗纵41.226→39.045ms看似有益，横向及静止却不一致；不能选择纵向数字掩盖回退。两轮计时块的补绘/重绘/缺块/驻留变化/淘汰全部为0。

额外分组大小轮74断言、2868有效间隔，两个大小各五个视角及恢复全部离屏RGBA精确。更细、更粗均不构成稳定双轴收益，不能由此推出其它任意树结构必定无效，也不继续盲调格子大小。

组级原生缓存v19：50断言、2392有效间隔。271组中74组开启缓存，保守像素估计16699334（含边界余量，不是实测内存），五个离屏视角和恢复均精确；总体反慢约10%。该策略按显示顺序消耗额度，未记录其中多少实际覆盖眼前物体，故只否定这个分配策略，不据此否定附近物体缓存。

补充v20仅包裹当前视口±512世界像素的连续Box组，分别对照不缓存/原生缓存，远处根保持原父节点。84断言、2868有效间隔，58个附近组、21个原本可见且非透明的子根确实获得缓存；保守像素估计15122218。两种模式各五视角及恢复离屏RGBA精确，计时块零补绘变化，所有覆盖/恢复断言通过；但仍没有完整帧收益。不能把这次负结果归结为缓存未覆盖视口，也没有理由扩成正式实现。原生Stage呈现仍标未验证，未以离屏相等冒充完整视觉门禁。

GC候选共3824有效间隔、25断言，阈值95/75各调用960次，实际总调用耗时735/835ms、单次最大138/118ms。它确实执行了回收工作，并非开关没生效；只是把停顿挪到主动调用处，没有消除。每块最后一帧的探针尾段为0ms，未见块边界丢掉某次长调用；仍保留首间隔剔除的采样边界。全部块零新增地形工作。

## 平台边界与进一步对照

官方[DisplayObject文档](https://airsdk.dev/reference/actionscript/3.0/flash/display/DisplayObject.html)说明`cacheAsBitmapMatrix`不支持桌面操作系统。原生`Box.as:405`已经设`vis.cacheAsBitmap=true`，不能把重设这个开关当作新优化。新的组级缓存与旧整层缓存的区别在于只合并连续精确Box根、排除角色和弹体；原生子物体变化仍会使其失效。仅`BitmapData.draw`相等不能单独证明原生Stage缓存呈现精确，若计时有收益还需真实呈现验收。

本机SDK运行库51.3.3.2的独立轮，实际进程载入路径、DLL版本和SHA已通过PSAPI只读核对；正式运行库未替换。`full`均值39.908ms、P99 99ms，不能直接与先前正式版42.886ms计算稳定收益：两轮自然单位132/142，时间环境不同。随后恢复51.1.3.3得到40.603ms、P99 79ms；新版与恢复轮均值仅差约1.7%，且纵移42.717ms比恢复轮40.500ms更慢。这不支持替换正式运行库，两轮合计7176有效间隔、104断言。恢复轮也重验中性分组40.603→42.984ms变慢，进一步否定把前两轮纵移小幅收益当稳定优化。

SDK自带`Release_Notes_AIR_SDK_51.3.3.pdf`第4页明确警告Windows ANGLE当前有显著问题和不稳定性，因此未启用。此次只换隔离进程的运行库，不换渲染模式。GC语义按官方[System文档](https://airsdk.dev/reference/actionscript/3.0/flash/system/System.html)核对：API会在临近回收时主动完成工作，并不是可设置“每帧GC预算”的接口。

## 收尾与剩余边界

本轮10次实际游戏运行，9次完成、1次预热超时保留；另1次排队超时从未启动。完整计时共29892有效间隔。汇总与冻结清单见[机器结果](../../build/generated/lossless-cut-survey-20261101/summary.json)、[原件清单](../../build/generated/lossless-cut-survey-20261101/archive.json)；包括候选精确源、SWF、构建回执、原始计时、加载指纹及环境，失败不抹去。

这些结果与前两轮证据共同覆盖目前可具体实现的主要低侵入切口，未留下满足“保留效果、双轴稳定且明显提速”的新候选。本轮**不部署任何新性能产物**，正式宿主仍9D8662F6，14个正式模组和两个运行库文件回读一致；前轮修复原生隐藏状态的版本保留。未改玩家配置、存档或他人工作。

目标仍未达到近原版，不能宣布数学意义上的“所有无损优化空间已经耗尽”。剩余证据指向原生显示树呈现与周期性回收；这不是证明“只有降画质才有解”。更大范围的绘制后端/对象呈现重写仍属未验证空间，需要新的具体实现和整帧、原生Stage及功能证据，不能将潜在路线写成已经证实可提速。本轮停止已否定的具体实现，保留可复核资料，避免下轮重复同样的缓存、分组参数和局部计时误判。
