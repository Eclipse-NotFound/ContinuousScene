# 动态模糊 / 双线性采样离线成本微基准（Lead，2026-11-04）

被测对象：Adobe AIR 桌面 CPU 软光栅下，**全屏后处理与位图重采样**的真实代价。目的是回答“镜头移动时背景粗糙 → 要不要引入动态模糊”，以及“地块开 `smoothing=true` 到底多贵”。

- 运行环境：本机 AIR SDK 51.3（`mods/Sandevistan/build/tools/airsdk`），`adl64.exe`，隐藏窗口，内容区 **2048×1123**（= 用户大窗口实测内容区 2032×1084 的同量级）。
- 被测 SWF：`mods/ContinuousScene/build/generated/filter-cost-20261104/FilterCostMeter.swf`（源码同级 `src/FilterCostMeter.as`，构建 `build-bench.ps1`）。
- 计时：`getTimer()`（1 ms 分辨率），每个测量内部循环 N 次后除以 N；每轮先热身 2 次，共 15 轮取平均，同时记录 min/max。
- **性质**：这是对“游戏合成器使用同一组原语”的离线代理测量，**不是**在游戏进程里测到的数值。它给出的是同尺寸、同软光栅路径下这些原语的成本量级，用来否定/保留候选方案，不能直接当作游戏帧时的增减。

## 2. 结论

### 2.1 动态模糊：否决（有实数支撑）

1. **最便宜的模糊也要 15~19 ms/帧**：`BlurFilter` 半径从 2 到 16 成本几乎不变（15.5~16.0 / 18.7~19.5），说明瓶颈是整帧带宽而不是卷积核大小。“半径调小就便宜”不成立。
2. **挂在世界容器上更贵**：容器带模糊后单次绘制 23.7~58.7 ms，比无滤镜的 4.4~11.9 ms 高 **+19 ~ +47 ms**；quality 3 时 43~45 ms。
3. 30 fps 的单帧总预算只有 33.3 ms，而当前真实游玩的整帧均值已是 33~45 ms、还有 >100 ms 长帧。**任何 ≥15 ms 的全屏后处理都会直接把游戏打到 15 fps 以下**。
4. 累积缓冲（把上一帧以 alpha 混合回去）只需 2.2~3.2 ms/帧，是唯一“价格可谈”的形式；但它对全屏生效，会把 UI、准星、角色、弹道一起拖脏，且这 2~3 ms 买到的是纯观感而不是性能，仍占 7~10% 预算。
5. 因此：**在本机 AIR 软光栅上引入动态模糊属于性能上不可接受、视觉上还会污染 UI 的路线**。若用户仍想看到效果，只能做成默认关闭的可选开关，并接受它换不来帧率。

### 2.2 双线性重采样（`smoothing=true`）：有条件可用

1. 只有当**世界被非 1:1 缩放**时才需要重采样：默认 1280×720 窗口 `scaleV≈0.6583`；大窗口 2048×1123 时 `scaleV` 被钳到 1。
2. 在 0.6583 下，双线性使 4 层合成从 2.1→6.0 ms（轮2）或 13.6→20.7 ms（轮1），即 **+3.9 ~ +7.2 ms/帧**，相当于 33.3 ms 预算的 **12~22%**；逐块路径下比例类似（+1.8 ~ +12.9 ms/层）。
3. 在 1:1 下双线性 **没有额外成本**（12.13 vs 12.40、1.97 vs 2.22）。
4. 结论：`smoothing` 不能无条件全开；应**按 `scaleV<1` 门控**，并且必须用真实帧时 A/B 验证（离线代理只能证明量级）。

### 2.3 负结果

- `cacheAsBitmap=true` 加在地块容器上**更慢**（+64%~+68%）：不要再用这个方向。
- 呈现一个已就绪的全屏缓冲只要 0.65~0.87 ms，因此“预先合成一张屏幕大小的位图再贴出来”在**呈现**环节是便宜的；贵的是每帧重新产生内容（这与本仓历次“屏幕像素缓存/半分辨率重画”负结果一致）。

## 3. 方法学限制

- 计时分辨率 1 ms；单测量内部循环摊薄后，误差主要来自系统负载而非舍入。
- SWF 为 **debug 编译**（`trace` 需要 debug SWF 才能在 ADL 下输出）。原生光栅调用不因 debug 变慢，但 AS3 侧（循环、闭包）略慢；对本文所有结论（均为原生原语）无实质影响。
- 所有测量写入离屏 `BitmapData`，不是舞台合成；舞台合成还会引入显示列表遍历、裁剪、缓存策略等差异。
- 产物与源码保留在 `build/generated/filter-cost-20261104/`，可直接复跑：`adl64.exe app-debug.xml`（需先按 `build-bench.ps1` 的 mxmlc 配方编译 debug 版）。
