# 固定场景下的镜头移动／世界显示层归因

只用于诊断，不能部署。用户2026-10-25再次要求以镜头移动本身为核心，无敌人与战斗都应流畅。活动范围候选保留，暂不优先实测。

本实验从准确29AF的85源生成86源，只改Main接入并新增测试helper。helper以88A4的原镜头诊断为基础，所有变换可反转，来源指纹固定。原绘制/地形/角色/镜头类不改，SceneTilePresentation也不改且不执行update，不引入合图或摘树。

地图准备好后暂停World模拟，保持玩家位置/速度/HP，仍保留Flash时间轴和其他帧回调。依序测世界可见静止、可见移动、隐藏静止、隐藏移动，再逆序；每段120帧，共960帧，连续计时。原Camera.calc仍执行，包含其原sceneTick；仅在隐藏臂临时设置world.visual.visible=false。这个开关涵盖绘制、命中检测和底层显示树工作，不能把差额直接称GPU时间。

测试限独立motion AIR应用。在既有私有Windows桌面把本轮NativeWindow设为可见，整个准备和计时阶段一致；不激活、切桌面、移动全局光标或发送输入。结束恢复原世界/窗口可见性、相机、缩放/显示矩阵、暂停、帧率和附属状态。

地图先沿整个路线反复预绘，最多12遍，八项原生绘制计数整遍不变才开始。计时中再逐帧核对它们；任何新增预绘、缺块或玩家状态变化均判失败，不裁掉帧。五个视口各做同帧可见／隐藏／恢复截图：隐藏必须确实改变大于100像素，恢复必须逐像素相等；15张临时位图全部释放。这不是新画面方案的像素验收。

helper沿用120fps诊断设定，原帧率记录并恢复。因此本实验只能比较条件性镜头开销，不能冒充真实无敌人行走或战斗FPS。若世界隐藏后移动额外开销仍在，应继续查显示树之外；若明显消失，再限定具体世界层及连续画面的修复，不把隐藏画面当优化。

run.py沿既有登记、4GiB提交余量预检、512MiB运行中保护、唯一AIR ID、独立存储和自有进程清理。冻结526正式输入、13运行库、85来源/86试验源码和完整脚本输入；原始错误与结果保留。当前源已准备，编译和运行状态见独立evidence记录。
