# 不修改宿主文件的镜头原生耗时对照

前轮basic telemetry实际收到3257097条记录、769帧后触及180秒接收时限，未取得自定义Telemetry.sendMetric标记，整轮失败。读取AIR本体发现子SWF的详细记录标记会被忽略；源侧准备的host tag93写入及精确grant均被本机hook拒绝，两条命令未执行。camera-axis-telemetry-v2保留准备状态，禁止借本目录重试它的宿主改写。

本目录沿已观测到的另一条通道：原生流确实有其他模组的.trace事件。只把测试helper的961条自定义标记换成带固定前缀的trace，经函数变量调用以保留编译调用；不改正式或隔离宿主任何字节，不依赖高级记录标记。以原生流实际返回全部961标记为成功前提，不能只看源码、字符串存在或connected=true。

其余静止/横/纵/组合960帧、逐帧八项原生计数、5视口10张原生重复截图、正式输入、私有桌面、唯一存储、清理门禁保持。继续实际1.BAT所用的默认ADL模式（当前文件没有-nodebug），不依据历史注释擅自换运行模式。

记录器仍只临时独占本机配置并清理，最长300秒/128MiB/8百万记录；本轮因已有启动与预绘用时证据调整采样总时限，不修改游戏的内存/实例保护。解析改为两次逐条读取，不在内存保存数百万事件：首遍核标记及完整流，次遍按名字和窗口合并跨度；保留真正的区间间隙，避免嵌套重计。原生成本仅用于归因，不能把带记录器的帧时间当正常游玩或产品提速。
