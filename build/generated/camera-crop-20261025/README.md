# 镜头裁块候选：离线源码准备

用户要求保留 B190 试玩窗口，先准备修复。本目录不启动 AIR、不自动排队测试，也不覆盖正式游戏。旧裁块曾有性能正向线索，但缩放、震动及 SATS 像素验证失败；本候选尚不能宣称修复了镜头卡顿。

## 候选行为

- 原生 400px 地形缓冲继续接收弹痕、破墙、涂色、水面和模组读取；显示时使用裁掉外围40px的320px副本，保留原 Bitmap 对象和图层顺序。
- 仅针对320px块；640px块继续原路径。只有无震动、SATS关闭、四个地形层到 Stage 的完整变换为单位比例且整数平移时启用。祖先有滤镜、遮罩、额外裁剪或非normal混合时也回原显示；水层原生透明度不阻止资格。其他情况立即回到原图与原 scrollRect，不改变玩家镜头位置。
- 资格变化纳入原裁剪缓存键；不会因为镜头还在同一组块内而漏掉回退。
- 可见副本在回退时保留，避免跳跃/震动导致反复分配。离屏时先回收，再给新进入视野的块分配；副本池最多64张。
- 场景原生动作及区域合成后同步受影响层；批量写入后强制同步四层，不能仅依赖 revision。SATS截图临时恢复原图，finally只恢复状态，不在那里分配副本。
- 原生绘制异常沿原路径抛出；候选恢复所有已绑定原图后禁用自身。候选自身的分配、复制或绑定失败亦回退并计数，不能抛出新异常盖掉原错误；验证必须要求失败与恢复错误计数均为零。

## 文件与验证范围

`candidate/scene-crop-presentation.as.inc` 是候选辅助代码。

`prepare.py` 先核验正式 A796 与已冻结的旧来源中六个目标方法语义一致，再只输出这六个方法的替换片段及辅助代码。**不能整类重编旧75157源码**：它没有正式版的颜色修复。修改范围为 `sceneCullSurfaces`、`sceneApply`、`sceneFinishBatch`、`sceneSats`、`sceneDrop`、`sceneClear`，不修改创建房间、AI或物理逻辑。

`compile_check.py --prepared <生成目录>` 仅把这些片段放进独立的动态 AS3 类做语法编译。512MiB JVM，保留4GiB提交余量/2GiB物理内存预检，登记为offline。动态宿主字段不会在这个检查中得到正式类类型验证，产物 `SyntaxOnly.swf` **不是游戏补丁**。

恢复实测后，先运行上一轮冻结的 `camera-raster-20261024` 诊断，核实当前整数平移是否有值得推进的差额。暂停不会关闭所有回调：原生 World 仍调用 Camera/GUI/Pip/SATS，诊断又调用一次 Camera，因此区间包含两次相机调用及模组回调，不是纯渲染毫秒，也不是游玩FPS。

只有明确收益成立后才组装实际A796宿主候选，并审计全部未改方法、类布局、原始素材和私有标识。还需验证整数视口像素、非整数/缩放/震动回退、即时弹痕/破墙/水、SATS、清图重入及 RV/WB/LAD 组合；最后以真实移动战斗对照判断是否部署。

RV等组合可能因上述资格保护而继续使用原显示。那只表示画面回退，不代表该组合获得加速；640px、带遮罩或滤镜的场景仍需另行证明可优化，整个镜头卡顿目标尚未完成。
