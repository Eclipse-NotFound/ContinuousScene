# Exact player leaf diagnostic

Only derived from the measured 29AF / f298932b38e24919991997c68e0a8b8a 85-source SMG fixture. Closure: modify `ContinuousSceneMotionProbe.as`, add default-package `SceneLeafCacheTrial.as`; 86 files, the other 84 unchanged. This directory does not build, run or deploy anything.

`cfg.drawControl="playerleaf"` retains all four 300-frame native-input sprint/fire windows. All windows are observations, **not cache ABBA or performance acceptance**. No cache flag is written during continuous timing. Read-only tree scans and their `scanMs` remain inside every interval. No additional position/velocity, equipment, window visibility/focus, timeline or AI writes.

Both the old pinok16 example and 29AF call `newGame(-1,"Scene Motion",{propusk:true})`; native `Invent.addMin` equips `pip`. The old actual tree showed `sleg3_52` at `pip`, containing exact `pfe_fla::sleg20_53` (one frame, one Shape). This does not guarantee every later pose contains it. A warm-up inventory therefore requires exactly one eligible target with actual `pip` armor; absent/ambiguous/ineligible is an inconclusive terminal result, never a substitute target or success. Equipment and actual Stage/nativeWindow properties (or individual read errors) are recorded at inventory and finish.

`leaf-inventory.json` is saved once before `startCase` starts continuous timing. It includes `initialWindow.stage` (displayState/frameRate/quality/stageWidth/stageHeight), `initialWindow.nativeWindow` (visible/active/closed/displayState/renderMode/bounds/applicationActiveWindowMatches), and per-property read errors. `renderMode` is the reported window setting, not proof of a hardware backend. Hidden/inactive status is not fabricated into a cache failure, and no code shows, activates, focuses or otherwise changes the window. Screen presentation remains unverified.

Stability rules fixed before running: all 1200 observations must contain one eligible exact native leaf; its leaf/parent/Shape identities and internal visual contents must be unchanged for the final 120 frames. More than one topology transition per 120 observed frames is classified as frequent replacement and rejects cache qualification. These conservative experiment thresholds are not engine guarantees. Parent transforms are recorded but intentionally excluded from content stability: whether a moving ancestor permits useful cache reuse remains unproved.

Only after the final timestamp and `closeProbeTiming(true)` does a successful/stable run make one same-frame whole-Stage A/cache/A comparison. Cached RGB delta must be <=2 per channel and alpha identical; restoration must be exact and restore the native leaf state. Three owned bitmaps are disposed in finally; the original flag is restored even on failure. An already failed gameplay run skips pixel work. Final pixels and their elapsed time are separate from the 1200 intervals. One terminal pose is not complete animation/scale/fractional-transform or OS-rendering validation; no speed claim follows from this component.

Before any terminal cache write, `pixels.visibility` records and requires the exact Stage identity, a visible positive-alpha ancestor chain, and finite nonempty `getBounds(stage)` intersecting the Stage viewport. This rejects an obviously hidden/offstage empty comparison but does not prove absence of foreground/mask occlusion. An exact zero-difference cached image is allowed; no artificial positive pixel difference is required.

API: `begin(w):Boolean`, `observe(w,windowIndex,frame):Object`, `snapshot():Object`, `finish(w,complete):Object`, `clear():Object`. Main reports `leafCache`, per-row `leafCache.frames/start/end`, and `leafCacheCleanup`. A non-qualified/inconclusive result must remain failed/inconclusive in the runner, not be accepted merely because cleanup succeeded.
