# 镜头基准黑区纠正与原生物件分组缓存：未获得明显提速

2026-10-27。六次隔离AIR、四个冻结程序，正式文件未变。**根目标仍未完成，没有部署。** 本批首先纠正一个重要测试范围错误，不能把最初的原版/大场景数字当正常游玩的性能基准。

## 黑区问题与证据限制

active-quiet-axis 用同一程序测试原版房间与大场景，真正关闭主菜单、保持模拟运行、移除隔离夹具敌人和旧弹体；两模式的地图/走廊指纹一致，960个相机坐标仅差3840/4000偏移。active-quiet-bands 又完整重做一对，逐间隔分解时间并严格加总。

但随后 near-groups 的保存PNG被实际查看，发现这条路线以房间局部Y=600为中心，而角色所处平台Y=120，画面几乎全黑。角色本身不在视野内。最初四轮没有保存完整画面，不能凭地形哈希和坐标相等证明测到了正常可见场景。四轮计时和 near-groups 原始结果保留，**代表性验收均撤回**。这不是程序执行失败，也不能把它们记成有效游玩基准。

该黑区中的原版/大场景分段均值：原生所在Stage监听区间约2.2–3.5ms，大场景移动时Stage回调间隔约14.7–16.1ms，静止8.26ms。只说明这条黑区路线的差异落在哪个时间段；不能据此宣称正常可见场景已定位到某个GPU函数。Stage回调间隔还含Flash回调、运行库和系统调度。源码MainMenu在Stage默认优先级0调用World.step，原生区间也可能包含其他同区间监听。

## 校正后的有效可见场景候选

visible-groups 以实际初始角色位置为镜头中心，保留横向±120、纵向±48的原生camRun+calc路线。角色全1920样本都在视野中。五张原生PNG已保存，第一张原生/候选完整PNG实际查看，角色、平台、建筑背景清楚可见。避开主要HUD边缘后的非黑像素占比60.5%–73.4%。该像素门槛只排除明显空黑区，不能取代图像查看或Windows实际窗口验收。

仅在六个物件层中，将顺序连续、位于路线附近的Box/Bonus图像置入原生cacheAsBitmap容器，原坐标、混合顺序、父层不变；不stop/play，不手工重画角色。原生引擎负责内容变化后的缓存失效。这轮选中15根（13 Box/2 Bonus）、5组，估算缓存688756字节；初始14个多帧剪辑、isPlaying计数0。这个初始计数不是全程静态证明。
