# 镜头绘制容差对照

前一版严格检查 `camera-raster-20261025-r2` 实际进入游戏后，在第一个视口发现600/2,202,688像素有颜色差异：全部RGB通道差值最多1/255，alpha完全相同；恢复原图后零差异。原检查按完全一致要求失败，没有进入960帧计时。三张截图位图均已释放，原生状态恢复通过；原失败保留，不改结果为通过。

用户此前明确接受继续测试这类微小颜色差异，要求先验证明显提速再考虑部署。本目录是独立v2，允许crop每RGB通道差值≤1且alpha零差；restore仍须逐像素完全一致。`equal`/`exactEqual`继续表示精确一致，`withinTolerance`另行记录，不能混用。没有允许旧方案中大于1的颜色偏差。

helper由旧88A44A源码只改report和pixelCase两处，SHA为 `7453D771C560AA602AE08D0CAB7F7F3842345E4C55EA85399D6BFB175FE8BC2B`；相机路线、五视口、8×120连续计时和清理逻辑未改。runner增加首个裁块窗口的复制/分配阳性检查，避免仅以零差异误认裁块已启用。

仍使用原生大场景、暂停World逻辑、临时120fps、原Camera.calc。暂停期间原生World仍调用Camera、GUI等，helper也调用Camera；因此只能比较此诊断内的差额，不能称纯渲染耗时或真实游玩FPS。未通过完整真实战斗及组合验证前不部署。
