# 同一实例内的环境键缓存对照

当前后继在AIR创建前，通过已实际完成seed及AIR运行的 `camera-live-current-silent-20261028/silence.py` 给新唯一ID预置原生Snd音量0，拒绝已有存储，并在结果核验时读取留存配置。仅覆盖原生音频；不会改变正式配置。该助手进入运行与探针编译回执的 `runnerInputs` 源码输入指纹，运行回执另记实际路径与SHA256，独立核验与实际加载来源对齐；冻结宿主构建的 `sourceInputs` 不变。游戏4GiB预检在真正创建进程前再次执行。

启动包装器只在游戏启动段安装，明确捕获当前登记lease，退出时在finally恢复原构造器，不影响此前独立的共享编译路径。参数、静音或内存预检失败且尚未调用进程构造器时，清除此lease的launching状态；一旦进入构造器，失败仍保留登记器的保守不确定状态。此修正只做生成与离线静态验证，paired夹具尚未编译或运行；相邻已构建binary目录及其冻结输入不改写。

首对分进程运行在地图准备数量和系统负载上不同，7.7%不能直接归因。此配方只为把原始键表达式和F15缓存表达式置于同一诊断宿主中切换；不部署诊断宿主，也不把额外选择分支当正式候选。

Grafon.sceneNativeEnvironment原方法的[66,117)键表达式保持原字节，缓存臂复用F15的原字节；公共选择分支先检查现有普通state对象的诊断属性。其他5770方法、1016类布局、原常量前缀及素材不变。构建后逐项核验。选择分支本身计入两臂，不扣除估算开销。

镜头沿native-once已验证的优先级500计划、原生0计算、-1000观测运行。16×120完整区间：静/横/纵/组合正反次序，对应原始与缓存各两次；保留边界混合区间、尖峰及主线程开销，零额外计时Camera.calc。两路径各做150种环境断言，五视角做原始/缓存/恢复图比较；同一对象、地图与已生成图块，不以两次启动的随机内容相同作为假设。

仍为1280×720、120fps、原生模拟活跃的无敌对对象终结式夹具；不是原版30fps、自然跳跃、真实战斗或显示器FPS验收。全程正式文件只读，游戏测试先登记，唯一APP ID/存储、私有桌面、当前资源策略，保持已有内存门槛。

尚在准备，是否通过以实际构建、运行及独立核验回执为准。旧配方及失败回执不改写。
