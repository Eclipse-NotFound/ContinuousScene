# 自有 AIR 原生线程位置诊断

只用于镜头/战斗成本归因，绝不作为性能改进或部署验收。正式 A796/CS7F1F/TDFC7ACD/RC78C/RV638E 保持；注册独占测试，唯一 AIR ID、私有桌面、原有 4 GiB 提交/2 GiB 物理预检与 512 MiB 运行保护全部保留。

沿准确 29AF 的 85 源测试，只在 Main 三处加入时间锚点，连续保留 4×300 帧、六名原生 SMG 敌人、真实冲刺/物理/双方子弹。没有强制坐标、消警戒、减火力、降画质或新缓存。相同 clock 变换已用于 thread-cpu-native。编译输入、526 正式文件、隔离输入、13 runtime 文件逐项冻结并复核。

第一次进程 CPU 回调（约创建后1秒）以原 HiddenProcess 绑定；35秒后准备一次线程清单/映像缓存，此后约每秒轮转最多两份，上限160份。每16份复查模块清单；未知/JIT地址保留IP并停止展开。首次准备及所有观察耗时留在实际测量，不扣帧，不比较本轮FPS。每次短暂停仅取上下文/有界栈，恢复后展开；不操作其他进程，不接收外部PID，不用符号服务/管理员录制/注入。

完整1200原间隔与26项功能断言、真实双方弹体/冲刺资格、原句柄/精确创建时间/私有桌面启动与线程归属、成对Suspend/Resume、退出/清理及输入守恒均必须通过。实际取样至少40份，其中至少10份完全位于测量时段。暂停长帧和所有读取/展开错误保留；多帧栈只说明工具返回的展开结果，没有独立栈真值；墙钟样本频率不当CPU占比。CPU累计差额单列，模块/RVA不直接命名渲染、GPU或脚本函数。

模块缓存128MiB是只读映像字节预算，不是整个诊断器内存硬上限；原生展开没有函数内部超时，24步/64KiB亦不是墙钟硬上限。运行仍受原600秒全轮看门狗限制，但它不能抢占阻塞原生调用。没有真实AIR能力结果前只算准备。

## v2 与 r1 的差别

r1 在首次线程准备的 GetThreadDesktop 返回 WinError5，0次暂停、0游戏栈样本；保留失败与原源。v2 不再请求这个线程桌面属性，也不改变桌面权限、不采用其他方式重取该信息。原始 HiddenProcess 私有桌面启动证明及句柄/PID/父进程/映像/描述符/精确创建时间、每条线程所属PID/TID/创建时间校验全保留。线程当前桌面没有验证，明确false；仅诊断自己新建进程的线程，不做任何桌面交互。

## IP-only轮次

本版替代此前模块缓存与栈展开：只读取RIP，不读取栈/模块内容、不展开。固定v2归属基类与原核心指纹作为依赖；每约秒记录全部初始持有线程CPU差额，最高者+其余两窗活跃者环形选择，一次最多2份。全部选择由结果复算验证；CPU区间保守用前次读取开始/本次读取结束判入测量窗，时长上下界分列。新线程仍不发现，不把偏置IP频数当CPU比例。实战仍准确85源clock探针、全526/13闭包及26检查。不部署。
