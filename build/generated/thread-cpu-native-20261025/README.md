# 原生战斗逐线程 CPU 诊断

准确 29AF/85 源仅 Main 增加首末和四段 UTC/getTimer 内存时钟锚。rcnative 四段各 300 帧，无合图、镜头固定、显隐或战斗行为改动。原生六 SMG10、玩家开火/冲刺/击退、普通预绘、全部连续间隔保留。

Python 每三次已有 owned process CPU 采样（约三秒）查询同一私有桌面 AIR 的线程计时与周期数。自有 Python 冒烟中 Toolhelp 每次约 150 ms，因此避免每秒枚举；实际采样耗时仍全部记录，不能与旧轮帧率直接比。只读查询，不暂停线程，不改优先级，不读其他进程线程；原测试启动/内存/占用/输入闭包和清理保持。精确 PID + thread creation time 区分线程复用，HWND 映射只说明窗口所属线程。

UTC 时钟锚与 monotonic 双钟必须一致；仅完整位于计时窗口内部的外部采样间隔用于 CPU 解释。新增/退出线程、查询错误、采样耗时全部记录，不补零、不外推整窗 CPU。周期数不换算时间。

本轮仅归因：没有优化臂，没有像素改动，不能作为部署性能验收。CPU 计时不区分等待/就绪、不提供调用栈或 GPU 时间；私有桌面不代表用户桌面实际呈现。

运行：`run.py --name thread-cpu-native-20261025-r1 --compile-probe --registry-wait 600`。复用需传原构建目录中与 compile.log 相邻的 `--probe-build`。每次新证据目录，失败保留，正式包不写入。
