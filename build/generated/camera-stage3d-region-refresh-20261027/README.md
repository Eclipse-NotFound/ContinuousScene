# 固定512平方区域的重绘成本

前一轮完整固定world缓存把暂停画面的移动间隔从29.658降到12.092ms；每帧重画2032×1084整个视口却从30.988升到41.333ms，其中CPU绘制24.5ms/次。两轮均不是动态实战，画面仍不符合RGB2门槛。此轮只回答局部重绘是否明显降低成本，不把固定区域当作完整变化追踪。

沿wholeworld-settle的完整缓存，在所有预备视口的交集中选择居中的512×512世界坐标区域。每个GPU区间用原生绘制重画这一区域并上传单独纹理；GPU画完固定世界后，先在区域内用不透明远景替换旧像素，再画新区域，避免透明部分留旧影。计时前预分配，记录绘制、上传、数量和首张区域内容。游戏模拟和动画仍在两个对照中等同固定。

沿8×120连续区间及反序配对，原生静止/移动、GPU静止/移动，保留全部长帧和边界工作。13像素候选刷新＋480计时刷新=493；预计8纹理、9CPU图、上传501、copies501（实际按完整世界分块数校验）。原生8项预绘计数必须不变，18组自然往返和13组恢复必须精确。候选RGB2失败仍明确拒绝，允许测成本，不允许部署。

私有桌面、唯一AIR ID、共享测试登记、内存预检、526正式文件/13运行库指纹、85源冻结种子与86源构建沿原配方。此轮没有修改正式源码、模组或游戏文件。

后续只有成本明显下降才值得实现真实动画/弹体/门/弹痕的旧新区域追踪；还须解决全图缓存的发光和文字像素差异、实际窗口呈现和实战验证。

API依据：[Context3D.setScissorRectangle](https://airsdk.dev/reference/actionscript/3.0/flash/display3D/Context3D.html#setScissorRectangle())使用视口像素坐标；裁剪不影响clear，因此这里以不透明远景绘制覆盖区域，并在finally撤销裁剪。
